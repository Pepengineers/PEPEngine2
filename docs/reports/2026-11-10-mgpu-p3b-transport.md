# P3b native snapshot transport

Worktree `p3b`, branch `codex/mgpu-p3b`, base `97f4fac4e4c4767c2495a0544c3cbce506780857`. Status **checks complete**. Debug build and both physical two-GPU validation runs passed.

P3b turns the accepted P3a slot protocol into native DX12 copies. P4 supplies two distinct physical adapters, their serialized P1 COPY queues, and runtime-wide resource/allocation IDs. P3b keeps three individually shared buffers and three consumer-local allocations per stream. Each shared buffer has two placed device views with separate resource identities and one common backing identity. The strong `PhysicalView.Resource` aliases its slot owner, so an executor or descriptor can retain both heaps and the resource. Resize checks outstanding GPU work and borrowed views before replacing a bank.

The shared heap uses DEFAULT, SHARED and SHARED_CROSS_ADAPTER with the required zero-valued ALLOW_ALL_BUFFERS_AND_TEXTURES heap-tier flag. The transport places only ALLOW_CROSS_ADAPTER buffer views. The import COPY queue opens the producer's original cross-adapter timeline through P1. Scoped Win32 handles close after native open. Buffer copies retain exact byte count. Textures use the linear buffer as a packed copy representation and keep optimal local 2D resources. Both devices validate typed single-plane formats and matching aligned subresource footprints, including rows, byte ranges, arrays and mips. See [shared heaps](https://learn.microsoft.com/en-us/windows/win32/direct3d12/shared-heaps), [copyable footprints](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device-getcopyablefootprints) and [COMMON handoffs](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ne-d3d12-d3d12_resource_states).

The typed color boundary requires A1 to prepare depth as a typed grid. S2 must prepare typed R32_FLOAT snapshots for sun, point and spot shadows and connect the matching existing consumers. Depth/stencil, typeless, planar and MSAA payloads receive explicit validation errors.

## P4 and P2b handoff

1. P4 reserves a source handle and its backing identity before producer writes. An already held native pointer or allocation identity returns Deferred. Exact retains the demanded version across source or slot backpressure. A successful Exact reservation provides symbolic version and both physical credits.
2. For a pre-recorded Exact chain, call `PrepareExact`, bind the reserved views and physical hazards in the graph, and record with `RecordExportCopies` and `RecordImportCopies`. The recorders emit COPY commands. PlanExecutor owns graph barriers and waits. `CommitExact` then binds real producer/export/import batch receipts in dependency order. A terminal batch signal may cover both copy boundaries. The standalone helpers produce separate signals and share the same recorders and commit checks.
3. An internal Exact reader uses `PrepareExactReader(ticket, queue)` before Execute. It pre-admits a reader credit and returns its physical view and version for the symbolic edge. `CommitExact` installs the model reader after binding import. `BindReader` checks its actual batch point against the captured pre-submit queue baseline. Bind all prepared reader receipts and release the Exact reservation before Poll. A following consumer Execute instead uses ordinary `AcquireReader` before its submit with the issued ImportReady point and strong owner. Source reuse needs producer and export source-copy completion. Shared reuse needs import and shared-read release. Consumer-local reuse needs all reader releases and the P3a Exact/display/previous holds.
4. Latest only prepares imports after completed export and only offers completed local snapshots. It preserves the newest completed candidate under backpressure. `Poll` observes original timelines without a CPU wait. Producer and readers hand off COMMON; standalone COPY uses promotion and decay at batch boundaries.
5. P4 serializes prepare/record/execute/commit on the same native queues. Cancel certifies that unbound work was unsubmitted. An uncertain partial submission must call `FaultSubmission`; the transport preserves all prepared storage and stops issuing work. A resize first invalidates the old epoch, then waits for credits and strong view owners to retire. Device removal faults the stream instead of interpreting UINT64_MAX as completed work. P4 owns teardown and fallback. Explicit `Shutdown` drains healthy affected queues while storage remains owned. If teardown cannot prove retirement, keep the transport alive and resolve that error before destroying it.

Production registration is owned by the integrator. Add `Include/Engine.RendererDX12/GDX12SnapshotTransport.h` and `src/GDX12SnapshotTransport.cpp` to the renderer project and corresponding filters. P4 owns graph/descriptor registration and technique wiring. No P0/P1/P2b/P3a or existing project source was edited.

## Authored fixture

`MGPUSnapshotTransportTests.vcxproj` is an independent native executable. It imports the existing P1 fixture project, replaces its source list with the new fixture and the transport cpp, and uses the accepted renderer library for P0/P1/P3a. The hardware test requires distinct hardware LUIDs. Lack of a second adapter is an explicit failure, as are unexpected HRESULTs including E_INVALIDARG.

- A 269-byte buffer fixture uses a gated producer, separately delayed export and import, independent reader timelines, a saturated Exact pool, and a demanded retry using the reclaimed local slot. It verifies readback bytes and sequence/epoch/checksum. The first invocation pre-records graph-style export/import/consumer lists before producer submission. It commits after all four submissions, rejects a stale reader point, holds the Exact pin until the prepared reader is bound, and accepts the already-issued reader receipt against its pre-submit baseline.
- The texture fixture covers 37×19 RGBA8_UINT, two array slices and five mips. It checks Latest while export and import are pending, same-frame and previous displayed selection, and exact readback per subresource. It resets with old import and reader work in flight, retains a borrowed view after GPU retirement, and only then recreates a 25×11 four-mip bank with a fresh epoch and IDs.
- Negative cases cover foreign and stale producer/reader points, unavailable stages, two source objects sharing one allocation, wrong source device or format, duplicate view identities, same LUID, depth/typeless layouts, exhaustion and cancellation of prepared reader credits, and partial external submission without a receipt. Sixteen bank/fence lifecycles after warmup check bounded process handles. D3D12 info queues on both devices must remain free of errors.

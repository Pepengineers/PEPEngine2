# Солнечные тени Bistro в MetaRenderGraph

## Реализация

Первый этап теней из переданного handoff: только солнце, затем пользовательская
приёмка. Локальные источники продолжают освещать сцену без теней. AO, probes,
SSR, прозрачность, симуляции и остальные дополнительные техники не включены.

Обычный Bistro использует `SceneSunShadows`. Диагностический `SceneShadows`
сохранён для отдельного `--smoke`; его карты, readback и упаковка в обычном
пути не создаются. Новый путь повторяет production `GDX12CascadedShadowPass`:

- Исходные `ShadowPass.hlsl`, `BuildShadowCascades` и `CSM.hlsli`: четыре каскада,
  texel snapping, границы casters, перекрытие и плавные переходы, PCF 3×3,
  normal bias, depth bias 500 и slope-scaled bias 1.5.
- Сохраняются CastsShadows, alpha mask и исключение прозрачных материалов и
  preview-сфер из теней. Солнце сохраняет авторские параметры и режим обновления.
- Один GPU culling формирует команды четырёх каскадов; четыре ExecuteIndirect
  рисуют прямо в области итогового depth-атласа 2×2. Нет упаковки, промежуточных
  карт или карт для выключенных probes.
- Атлас, indirect-буферы и счётчики принадлежат кадровому слоту. Зависимости,
  UAV/indirect/depth/SRV-состояния и время жизни задаёт Meta graph/executor.
  Старый Execute не вызывается.
- Четыре GPU-буфера сцены сохраняют существующие проверки revision и identity.
  CPU-границы casters пересчитываются только при изменении этих данных;
  движение камеры пересчитывает только каскады. Константы берутся из кадрового
  ShadowCB, без чтения write-combined памяти и копирований на каждый объект.

Качество: 2048×2048 на каскад, атлас 4096×4096 D32/R32. Это зарегистрированный
default App (`SunShadowCascadeResolution` и `D3DHelpers.cpp`); в исходном
`Config/Engine.ini` нет override солнечного разрешения. Ручные quality presets
App могут менять его; их сохранённый пользовательский выбор сюда не переносится.
Диагностические 512/128 не используются. Локальное разрешение остаётся 0.

## Уже выполненные действия

Release x64 собран успешно. Sandbox-сборка встретила известный C1902 службы
PDB; сборка вне sandbox прошла. Остались прежние LNK4099 внешних библиотек.

До уточнения пользователя обычный запуск показал Bistro с солнечными тенями.
Видимый заголовок показывал около 115 FPS; Task Manager — 98% GPU, отдельный
отсчёт nvidia-smi — 99%. Это разовые показания, не замер производительности и
не доказательство отсутствия CPU bottleneck во всех ракурсах.

Список установившегося кадра из `Logs/opaque-steady-operations.txt`:

```text
reset visible counts
GPU scene culling
scene depth ExecuteIndirect
scene GBuffer ExecuteIndirect
sun reset visible counts
sun cull four cascades
sun atlas four cascades ExecuteIndirect
initialize deferred HDR target
clustered deferred lighting
opaque HDR display transform
frame end / PRESENT handoff
```

В этом списке нет повторной загрузки статической сцены, упаковки карт,
диагностических копий и проходов исключённых техник. При первом кадре остаются
первичная загрузка сцены и подготовка IBL. В просмотренном логе явных ошибок нет.

Пользователь остановил computer-use клавишей Esc и уточнил: больше не проверять,
только запустить приложение и передать ему для проверки. Дальнейшие проверки
остановлены; движение камеры не проверено. Новые тесты, расширенный `--smoke`,
профилирование и матрицы режимов не запускались. Приёмка FPS/CPU/GPU и изображения
остаётся за пользователем; ≥95% во всех условиях не подтверждается.

Исполняемый файл: `Build/bin/x64/Release/App.MetaRenderGraph/App.MetaRenderGraph.exe`.
К локальным теням и другим техникам без следующего решения не переходить.

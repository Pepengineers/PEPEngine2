# Вода на двух GPU: результат проверки

Дата: 2026-11-12. База реализации: `4801cd88`, ветка `codex/bistro-rendering`.
Реализация: `c4470c03`; проверочные инструменты: `64868ad3`.

## Объём и статус

Существующий solver воды перенесён на дополнительную карту. Численная модель, параметры и оптимизации сохранены; `FluidSolver.hlsl` не изменён. Старый MGPU runtime не восстановлен, остальные техники не перенесены.

После уточнения пользователя проверка ограничена участием двух GPU и корректностью передачи. Дальнейшие запуски и сравнительная кампания FPS остановлены. Все созданные для проверки задачи запуска и тестовые приложения на MisSpec остановлены/удалены. Текущий checkout MisSpec не переключался: использован отдельный worktree.

## Устройство пути

- Вторичная карта постоянно хранит и считает `GDX12FluidSolver` в отдельном потоке. Входы settings/transform, batch Count/Dt и число фактически выполненных шагов привязаны к публикации. Масштаб времени мира и пауза сохранены.
- Через три shared cross-adapter heaps/placed buffers передаются только позиции `float3`, 12 байт на частицу. Скорости, плотности, сортировка и промежуточные состояния остаются у вторичной карты.
- Ready/consumed fences защищают публикацию и повторное использование слотов. Основной поток принимает только завершённый результат и в обычном кадре не ждёт solver на CPU.
- При заполненном обмене solver продолжает считать без публикации. Пока нового результата нет, отображается последний готовый. Начальное состояние доступно до первой публикации.
- Поверхность, освещение и композиция остаются на основной карте. PreviousPosition обновляется по предыдущему показанному состоянию; повторный показ даёт previous=current. Для движения локального контейнера сохранена предыдущая матрица.
- Нет ограничителя FPS, freshness/debt требований, политики Performance/Quality, автоподбора частот или переноса других техник.

Выбор startup-only, индексы из `WaterOffloadGpuTests.exe --list`:

```ini
[ConsoleVariables]
Render.PrimaryAdapter = 0
Render.Fluid.SecondaryAdapter = 1
```

`SecondaryAdapter = -1` оставляет обычный однокарточный путь. Одинаковый адаптер в обеих ролях отклоняется.
Схема обмена сверена с [Microsoft D3D12 Shared heaps](https://learn.microsoft.com/en-us/windows/win32/direct3d12/shared-heaps).

## Подтверждённая работа двух GPU и передача

На MisSpec использованы **NVIDIA GeForce RTX 5050** (основная, LUID 0:47217) и **Intel Arc B570** (solver, LUID 0:59621). AMD Radeon не выбиралась для выполнения техники.

Выполнен Release-тест:

```text
WaterOffloadGpuTests.exe --validate --primary 0 --secondary 1
```

Он действительно запускает production solver на обоих устройствах, читает позиции/скорости GPU и отдельно сравнивает отправленные и принятые позиции. Debug layer и GPU-based validation включены.

| Проверка | Результат |
|---|---|
| Одинаковые реальные шаги, входы и dt, оба режима, 257/1025 частиц | Пройдена, значения конечны |
| Максимальная ошибка позиции | 9.53674e-7 |
| Максимальная ошибка скорости | 8.9407e-8 |
| Точный payload конкретных публикаций | Побитное совпадение, без допуска |
| 10 публикаций и 30 повторных показов на каждом fixture | Пройдены |
| Заполнение всех трёх слотов, 3 цикла повторного использования | Пройдено |
| Четвёртый расчёт при заполненном обмене, учёт непубликовавшихся шагов | Пройдено; 22 реальных шага, 10 публикаций на режим |
| Начальная вода до первого результата, recreate и непотреблённый результат при уничтожении | Пройдены |
| Worker без Present | Получена публикация с 3 выполненными шагами |

Численный допуск заранее задан: `abs(error) <= 1e-4 + 1e-4 * max(abs(a), abs(b))` по компоненте позиции/скорости. Он допускает межвендорное FP-округление в короткой последовательности. К пересылке допуск не применяется.

В реальном Bistro вода содержит **100 980 частиц**. На результат передаётся **1 211 760 байт**. В завершённых прогонах лог вторичной карты фиксирует 3267 и 8157 реально выполненных шагов; импортировано 149 и 330 результатов соответственно. Это счётчики всей жизни экземпляра, включая прогрев, а не сопоставимый замер производительности.

Сохранённая ETW-запись App PID11700 содержит устройства на двух различных аппаратных адаптерах. Подтверждение исполнения на обеих картах и целостности данных основано на выполненных GPU-расчётах/readback, не на процентах диспетчера задач. Точный процент загрузки и длительность перекрытия здесь не заявляются.

## Изображение и время жизни

`WaterOffloadBistroTests` выполнен на той же паре с production Bistro pipeline и D3D12 debug layer. Вода видна, позиции действительно меняются. Проверены seed/advanced/paused/moved/reset/recreated/resized/reenabled и queued shutdown, без ошибок debug layer или device removal.

При паузе в снимке 82 301 водный пиксель, движущихся водных пикселей 0. При движении контейнера 92 827 водных пикселей с конечными ненулевыми motion vectors. Это проверка наличия/конечности движения; отдельного численного oracle для каждого вектора нет.

Снимки HDR, owners, geometry, motion и PNG-превью сохранены локально в `Build/water-evidence/bistro-images/`. Транспортный лог: `Build/water-evidence/two-gpu-validation.log`. GPU ETL: `Build/water-evidence/offload-gpu.etl`. Данные крупных трасс не включены в коммит.

## Остальные проверки и ограничения

- Успешные Debug x64 сборки App, WaterOffloadGpuTests, WaterOffloadBistroTests, FluidSortGpuTests, BistroRenderGraphTests и SecondGroupTests; Release App и GPU-тесты собраны на MisSpec.

- Новые Pack/AdvanceDisplay kernels проверены локально с GBV и побитным readback, включая повторный показ.
- Независимое ревью по шести направлениям завершено; исправлена гонка фиксированного 100ms ожидания в тесте. `git diff --check` проходит.
- Сравнительные FPS, полное GPU-время основной карты и длительный soak не завершались после сокращения объёма пользователем. Прирост FPS не заявляется. Общий frame GPU timer исключает отдельный submission импорта, что явно отмечено в benchmark JSON.

Посторонние изменения `BistroAdditionsTests.cpp`, terra-validation report, `imgui.ini` и `tools/tests/__pycache__` сохранены. Push в origin не выполнялся; передача на MisSpec сделана через разрешённые git bundles.

# Гибридная сортировка воды — 12 ноября 2026

В production оставлен **блок 1024**. На RTX 4080 SUPER он дал наименьшую медиану
во всех проверенных COMPUTE-сериях. На DIRECT он также не проиграл по медиане,
но на ключах Hash первые два повтора дали ничью с 2048. Поведение проверенных
симуляций совпало с исходной сортировкой побитово.

## Что изменено

Начальные стадии bitonic-сортировки выполняются в groupshared memory, затем
каждый большой этап объединяет глобальные проходы с локальным хвостом.
Сохраняется лексикографический порядок `(bucket key, particle index)`, включая
padding. Это сохраняет порядок суммирования вкладов соседей. Новые буферы,
bindings и параметры качества не добавлены; физические ядра не изменены.
Оба пути `LegacyTracked` и `PlacedUav` используют общее расписание solver.

При Capacity=65536 исходная сеть требует 136 сортировочных dispatch на подшаг;
блоки 512/1024/2048 требуют 36/28/21 соответственно. Выбранный 1024 уменьшает
полное число dispatch одного Record с тремя подшагами с 421 до 97. При
Capacity=1 сортировка не запускается. Размер 1024 явно передаётся из C++
компилятору двух новых ядер; shader default согласован с ним.

## GPU-замеры

RTX 4080 SUPER, драйвер 610.88; DXC, runtime target cs_6_8, оптимизация -O3.
Тестовый executable собран штатным Debug MSBuild; debug layer и GBV выключены
в benchmark. Это отдельный тест без загрузки Bistro, Present и конкурирующих
проектных GPU-запусков. Сборки и прогоны сериализованы с чатом диагностики.

Для каждой очереди выполнены три независимых запуска; в каждом четыре набора
входов, 51 раунд с детерминированно перемешанным порядком исходной сортировки
и трёх блоков. Перед каждым набором — минимум 1000 мс суммарного GPU-времени
сортировки всех вариантов. Между запусками есть CPU waits и upload; это
не непрерывная GPU-нагрузка. Перед каждым измерением загружается одинаковый
снимок ключей. Таймстемпы охватывают sort dispatch и UAV-барьеры, исключая
Hash, upload, переходы начального состояния, offsets и readback.

`fluid_hash` — реальные результаты production Hash для взаимодействующей
тестовой решётки из 51975 частиц, Dt=0.0001. Это не снимок загруженной сцены
Bistro. `random` — отдельные равномерные ключи с фиксированным seed. Все
варианты и исходная сортировка находятся в одном executable каждого запуска.

Для fluid_hash сортировка с 1024 занимает примерно на 73% меньше GPU-времени,
чем исходная. Более крупный 2048 сокращает число dispatch сильнее, но не даёт

на DIRECT, а на DIRECT fluid_hash находится рядом с 2048. Поэтому оставлен
один фиксированный размер 1024, без runtime автоподбора.

Третий COMPUTE-запуск шумнее; он сохранён и включён в сводку. В paired-сравнении
fluid_hash 1024 быстрее 2048 в 45/44/49 из 51 раунда COMPUTE. На DIRECT это

DIRECT-повторов равна нулю. Строгое преимущество 1024 над 2048 на этом DIRECT
наборе не заявляется. Межочередное сравнение абсолютных времён не было целью.

## Сохранение поведения и сборка

- Финальный `--validate` прошёл с D3D12 debug layer и GPU-based validation,
  ошибок ERROR/CORRUPTION нет. Run: `WaterSortSelectedValidate`, 10.34 s.
- Полные пары и offsets сравнены с независимым CPU lexicographic oracle для
  17 размеров от 1 до 1048576, включая границы 512/1024/2048 и padding.
  Проверены random, одинаковые минимальные/максимальные ключи и обратный порядок;
  для миллиона частиц используется random. Все четыре варианта прошли.
- Симуляция на 3/2049/51975 частицах проверена для legacy и near-pressure:
  после каждого Record с 1, затем 3 и ещё 3 подшагами побитово совпадают оба
  полных particle buffer, density, keys и offsets. Проверены конечность значений,
  реальное изменение скорости и cumulative ping-pong head.
- Сравнение включает отдельные 512/1024/2048 и фактический production Record
  в `LegacyTracked`/`PlacedUav`. Для 2049 дополнительно выполнен production
  DIRECT→COMPUTE→DIRECT с завершёнными flush/readback перед сменой очереди.
  Сравнение — с исходной глобальной сетью на COMPUTE.
- Четыре CPU-теста `tools/tests/WaterSortScheduleTests.py` прошли. Независимые
  агенты и ревьюер проверили сеть сравнений, pair ownership, barriers и states.
- 18 компиляций новых ядер: PresortCS/MergeTailCS × 512/1024/2048 × DXC cs_6_0,
  DXC cs_6_8, FXC cs_5_1 — прошли. До принятия параллельной SM6-only правки
  также сравнивался исходный байткод: шесть прежних ядер идентичны в DXC;
  первые пять идентичны в FXC, исходный Integrate в FXC уже имел ошибку unroll.
  Текущий runtime — DXC-only; эта отдельная миграция не приписывается воде.
- Финальные штатные Debug-сборки fixture и App прошли. Последний App build:
  `Build/WaterSortGpu/build-app-final.json`, 11.83 s. Диагностика получила RELEASE
  GPU/build window только после завершения этих работ.

Из корня репозитория, в окружении Visual Studio с доступом к Windows SDK:

```powershell
msbuild Apps/App/FluidSortGpuTests.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64 /m:4 /nr:false
Build/bin/x64/Debug/FluidSortGpuTests/FluidSortGpuTests.exe --validate --adapter 0
Build/bin/x64/Debug/FluidSortGpuTests/FluidSortGpuTests.exe --benchmark --adapter 0 --rounds 51 --output compute.json
Build/bin/x64/Debug/FluidSortGpuTests/FluidSortGpuTests.exe --benchmark --direct --adapter 0 --rounds 51 --output direct.json
```

В этой итерации запуск выполнялся через `tools/agent-skills/peengine-perf/scripts/run_job.py`:
600 s timeout, уникальные копии exe, snapshot source и 68 fingerprints exe/DLL/source.
Все входы до/после каждого принятого запуска совпали. Исходники compiler/device
были заморожены их владельцем; benchmark включал принятую SM6-only итерацию.
После COMPUTE-серий в fixture добавлен только выбор DIRECT и согласован shader
макрос по умолчанию; все сравниваемые варианты по-прежнему компилируются с явным
размером. Финальная validation относится к последней версии.

## Ограничения

Измерено время изолированной сортировки на одном физическом RTX 4080 SUPER.
Время всего solver и FPS сцены не измерены; frame baseline Bistro ранее не
дошёл до первого кадра из-за подготовки сцены. Нет визуального A/B, длительного
soak и проверки передачи между двумя физическими GPU. Тесты покрывают выбранные
входы и режимы; они не являются исчерпывающим доказательством для всех состояний.
Размер блока не объявляется универсально оптимальным для других архитектур GPU.

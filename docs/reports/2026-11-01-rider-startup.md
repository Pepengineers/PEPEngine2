# Rider: загрузка, память и частота кадров Bistro

## Куда уходят оставшиеся 15 секунд

После native-кэша выполнены два последовательных Debug-запуска с временными
wall-clock таймерами: **15,08 и 14,78 с до завершения первого кадра**. Контрольный
Release — **10,11 с**. Все запуски с готовым кэшем, без одновременной сборки;
приложение запускалось напрямую, без Rider/debugger. Фоновые приложения Windows
не отключались. Новых ошибок в трёх логах нет; каждый содержит два native cache hit
и ни одного Assimp source import.

Непересекающиеся этапы второго Debug-запуска:

| Этап | Время |
|---|---:|
| Инициализация рендера | 2,335 с |
| Чтение и проверка native-геометрии | 1,289 с |
| Подготовка 308 текстур | 3,027 с |
| Подготовка и загрузка геометрии в GPU | 3,381 с |
| Создание материалов и их GPU-текстур | 3,033 с |
| Остальная публикация сцены, освобождение CPU-текстур | 0,625 с |
| Прочая инициализация, включая финальный resize | 0,137 с |
| Первый кадр и ожидание его завершения | 0,956 с |
| **Всего, с округлением** | **14,783 с** |

Что находится внутри этих этапов (времена ниже уже входят в таблицу):

- **Геометрия:** `GDX12GeometryBuffer::AddMesh` занял 3,381 с. Из них
  `vector<Vertex>::resize` — 1,603 с, копирование частей и заполнение
  `PreviousPosition` — 0,537 с; создание/заполнение/передача vertex buffer —
  1,179 с, index buffer — 0,035 с. Внутри vertex upload сам `memcpy` — 0,092 с,
  ожидание очереди — 0,427 с. Ожидание index upload — ещё 0,014 с.
  В Release CPU resize/fill уменьшаются до 0,551/0,137 с, весь AddMesh — 1,833 с.
  Код при добавлении второй сцены расширяет общий CPU-массив и заново создаёт
  GPU-буферы полного размера. Vertex upload копирует весь CPU-массив, затем
  прежнюю GPU-геометрию и ещё раз новый диапазон. Это повторная работа после
  чтения кэша, а не повторный Assimp-импорт.
- **Материалы:** сборка diffuse alpha из opacity mask для 15 комбинаций —
  1,398 с Debug / 0,144 с Release. Создание GPU-текстур — 1,220 с Debug
  (включая промежуточный upload flush), создание 202 материалов — 0,322 с.
  Результат смешивания diffuse/mask пока не сохраняется на диск.
- **Текстуры:** 280 из 308 загружаются из BC7 DDS, 28 diffuse/mask PNG
  декодируются заново, поскольку для смешивания нужны исходные RGBA.
  Самые долгие задачи — `buxus_diff.png` (0,509 с) и `buxus_mask.png` (0,324 с).
  Используется 39 последовательных пачек по 2–16 задач. Оценка памяти берётся
  из исходной несжатой картинки даже при готовом BC7-кэше, поэтому она ограничивает
  параллелизм сильнее необходимого для cache hit. Wall-clock всей стадии —
  3,027 с; суммы длительностей параллельных задач нельзя прибавлять к этому числу.
- **Рендер:** 63 вызова компиляции шейдеров занимают 1,792 с из 2,335 с
  инициализации. `CompileShaderDXC` каждый раз читает HLSL и запускает DXC;
  чтения готового shader bytecode из кэша в этом пути нет. В Release компиляция
  всё ещё занимает 1,701 с. Финальный resize — только 0,116 с, начальные
  indirect-команды — 0,001 с: это не основные задержки.
- **Первый кадр:** 0,027 с update, 0,531 с CPU wall-clock рендера, затем
  0,398 с ожидания GPU. Внутри CPU wall-clock 0,405 с занимает проход локальных
  теней с первой подготовкой ресурсов/команд; это не GPU timestamp этого прохода.
  Два кадра в диагностическом запуске недостаточны для оценки установившегося FPS.

Приоритет следующих изменений: кэш готовых diffuse+alpha текстур (убрать и
повторное декодирование, и смешивание), кэш DXC bytecode с проверкой include/defines,
затем однократное резервирование геометрии для всех частей сцены и передача только
новых диапазонов. Отдельно уточнить оценку памяти для DDS cache hit, сохраняя лимит.
Это направления оптимизации; достигнутое ускорение ими пока не измерено.

Артефакты: `Build/startup-profile-debug-{1,2}.json`,
`Build/startup-profile-release-1.json`, соответствующие Debug `.log` и
`Build/startup-profile-release-latest.log`. Временные таймеры удалены из исходников
после измерений; существующие изменения сохранены. Дополнительных GPU Flush
профилирование не добавляло.

## Дополнение: готовая геометрия движка

По следующему запросу пользователя assbin заменён на `.pepmesh`: бинарные массивы
`Vertex`/индексов, bounding boxes, имена частей, все поля материалов и пути текстур,
кости, диапазоны и веса skinning. На cache hit возвращается готовый `Mesh` до создания
`Assimp::Importer`. Старые assbin-файлы не читаются и не удаляются автоматически.

Native v1 — локальный little-endian Windows-кэш с фиксированными размерами POD.
Ключ учитывает source/MTL size/mtime, параметры импорта, версию Assimp и формата;
header, границы записей, индексы, enum/bool и SHA-256 проверяются при чтении. Ошибка
чтения приводит к повторному импорту. Запись идёт во временный файл и публикуется
переименованием только после закрытия; отмена/ошибка оставляют прежний файл целым.

Замеры 2026-11-01 на той же машине (фоновая нагрузка не изолировалась):

| Этап | До, assbin | После, native Mesh |
|---|---:|---:|
| Геометрия Debug | 11,06 с | 1,33 с |
| Геометрия Release | 3,10 с | 1,15 с |
| Полный запуск Debug | 21,79 с | 15,71 с |
| Полный запуск Release | 12,11 с | 9,75 с |

Оба warm-лога содержат два `Engine mesh cache hit (no Assimp import)` и не содержат
`Assimp source import` в новом запуске. Debug читает файлы, созданные Release.
Два native-файла Bistro занимают 696 571 920 байт (около 664 МиБ). Первая генерация
геометрии из OBJ с уже готовым кэшем текстур заняла 17,37 с до первого кадра.
Результаты: `Build/native-mesh-{cold-release,warm-release,warm-debug}.json`.

LoadingTests дополнен точным сравнением всех сохранённых полей, UTF-8 путей,
проверками версии/размеров/контрольной суммы/индексов, усечённого файла и отмены
записи без потери старого кэша. Проверяются также реальные изменения геометрии OBJ
и материала MTL между запусками. Исходники ассетов не изменялись этим дополнением.

## Подтверждённые причины

- Исходный Debug-запуск в `Engine.log`: 18:17:26–18:21:29 UTC, около 242 секунд.
  Импорт OBJ занимал 211,7 с, текстуры 17,3 с, публикация GPU-ресурсов 10,0 с.
  Главный поток не обрабатывал сообщения окна во время ожидания загрузочных задач.
- После upload реестр продолжал держать примерно 5784 МиБ CPU-пикселей. Те же
  несжатые текстуры вместе с геометрией и render targets превышали 6 ГиБ VRAM
  RTX 3060 Laptop: WMI показывал около 7,29 млрд байт GPU committed и 1,25 млрд
  байт shared. Размер PNG на диске не отражает размер RGBA с mip-уровнями и копиями.
- Все 135 локальных светильников принудительно обновляли тени каждый кадр:
  755 ракурсов с повторным рисованием неподвижной геометрии. Изолированный GPU-профиль
  показывал около 6,8 с на этот проход. Эти диагностические Flush/таймеры удалены.
- Счётчик FPS ошибочно принимал любой прошедший интервал за одну секунду. Также
  `GameTimer::Reset` оставлял время паузы, а обработчик `WM_SIZE` повторно вызывал
  `SetWindowPos`, вместо обновления сохранённого размера клиентской области.
- Interior MTL ссылался на отсутствующий `Paris_CeilingFan_01A_emi.png` при нулевом
  emissive. Удалена эта ссылка; тест теперь проверяет существование всех MTL-текстур.

## Исправления

Окно показывает этап/время загрузки и обрабатывает сообщения во время работы общего
JobSystem. Esc/закрытие запрашивают отмену; текущие библиотечные операции завершаются
или доходят до callback отмены. Исправлены таймер, расчёт FPS и обработка размера.

В `Build/AssetCache` сохраняются производные Assimp-импорты и BC7 DDS. Исходники
не заменяются. Ключ включает путь, размер/mtime исходника, зависимости MTL и
версию/опции импортера. Маленький список MTL кэшируется отдельно, чтобы не сканировать
весь OBJ при каждом запуске. Повреждённый DDS или нечитабельный assbin перестраивается.
Это кэш по метаданным, не по хэшу содержимого: после внешнего редактирования с
сохранением размера и mtime следует удалить соответствующий кэш.

Размеры текстур и mip-цепочки сохранены. BC7 является сжатием с потерями; маски и
diffuse, которым нужно объединение opacity на CPU, оставлены несжатыми. CPU-пиксели
выгружаются только после завершения GPU fence. Сжатие выполняется через существующий
DirectXTex/D3D11, доступ к immediate context сериализован; при ошибке остаются
исходные пиксели с диагностикой. Кэш этой сцены занимает примерно 1,76 ГиБ.

Статическая геометрия рисуется в отдельные карты локальных теней и повторно используется;
движущиеся объекты накладываются поверх сохранённой глубины. Изменение статической
сцены/света инвалидирует кэш, исчезновение движущегося объекта убирает старую тень.
Все источники света и разрешение теней сохранены. Неиспользуемая генерация тангенсов
отключена для Bistro: PBR восстанавливает базис из производных. Только translation unit
импортера оптимизирован в Debug с сохранением PDB.

## Замеры и проверки

Машина пользователя: Ryzen 7 5800HS, 32 ГБ RAM, RTX 3060 Laptop 6 ГиБ. Полные
Exterior + Interior, 308 подготовленных текстур, существующие движущиеся предметы.
Файловый кэш ОС не сбрасывался; сравнение прикладное, не изолированный benchmark.

- Первая подготовка BC7/assbin в Release: 65,65 с до первого завершённого GPU-кадра.
- Повторные Release-запуски: примерно 11–13 с до готовой сцены.
- Итоговый Release (`startup-verified-release.json`): 12,114 с до первого кадра,
  43,955 мс/кадр на 120 последующих кадрах (22,75 FPS), working set 1,90 ГиБ,
  private commit 4,67 ГиБ, пик working set 4,20 ГиБ. Это не обещание 60 FPS.
- Повторный Debug: 21,8 с в benchmark; около 24 с непосредственно через Rider MCP.
- Итоговый Debug (`startup-verified-debug.json`): 21,788 с до первого кадра,
  59,357 мс/кадр на 120 последующих кадрах (16,85 FPS), working set 2,19 ГиБ,
  private commit 4,92 ГиБ, пик working set 4,37 ГиБ.
- В обычном цикле Rider Debug зафиксировано 17,7–17,9 FPS и `Responding=True`.
- Working set после загрузки: примерно 1,9 ГиБ Release / 2,2 ГиБ Debug, вместо
  примерно 9 ГБ исходного процесса; private commit около 4,7–4,9 ГиБ. Это метрики
  процесса, а не суммарная память Windows из пользовательского скриншота.

Финальный benchmark записывает время первого GPU-кадра, среднее время последующих
кадров с обычным CPU/GPU-конвейером, текущую и пиковую память. Локальные результаты
и журналы сборок находятся в игнорируемом `Build/startup-*`.

Проверены Debug/Release x64 сборки App; LoadingTests (таймер, lifetime текстур,
геометрия без тангенсов, отмена, инвалидация source/MTL, восстановление повреждённого
DDS, BC7 pixels/mips); пять Python-проверок сцены; LightingGpuTests с D3D12 debug layer,
чтением глубины статических/динамических теней и удалением исчезнувшего caster.
ReflectionProbeTests также прошёл: radiance/depth, кэш и публикация, PBR opaque/glass,
XeSS reset/resize, переключение режимов и смешанные пробы с D3D12-валидацией.

Windows была заблокирована: визуальное сравнение всей сцены, физический ввод камерой,
перетаскивание/resize окна и длительный прогон не подтверждены. Холодный Debug после
удаления всех кэшей не измерялся. Полная сцена всё ещё не появляется мгновенно;
окно загрузки доступно раньше и сообщает текущую работу.

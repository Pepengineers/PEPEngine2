# Сравнение графиков Bistro

Проверка версии `202c7173` от 28 ноября 2026 года. Сценарий — найти участок маршрута, на котором две почти совпадающие кривые расходятся, и прочитать разницу между проходами. Проверены окно сравнения, результаты при свёрнутой истории и автономный HTML-отчёт.

## Проверка исправлений в `5ffe3765`

Свежий экспорт приложения проверен в Chromium. Два нажатия `+` оставляют интервал 18–82 с. В режиме Upscaled внутри шкалы Y видны все 3047 кадров A и 3978 кадров B в этом интервале. Для Native результат — 2575 и 1151 соответственно. Переключение на FPS сохраняет те же 18–82 с. Щелчок фиксирует выбранный момент, поэтому при переходе к подробностям номер кадра сохраняется.

При ширине 600 px вся панель команд помещается в одну строку. При 390×844 и 844×390 значения A/B и разность видны без прокрутки. Эмуляция сенсорного ввода подтвердила сдвиг увеличенного окна вправо и влево отдельными нажатиями. Проверка охватывает Chromium на Windows.

В приложении на 1280×800 на участке 53,3–65,1 с видны график, закреплённое время, оба измерения, B−A, действия и легенда. Они помещаются и в окне 510×680. Для несовместимой пары приложение показывает оба измерения и причину отсутствия дельты. Переключатель истории переехал в верхнюю панель Results. [Снимок приложения после исправлений](../images/pepengine2-ui/chart-review/verified-native.png) · [Реальный HTML с закреплённой точкой](../images/pepengine2-ui/chart-review/verified-report.png) · [Тот же отчёт при ширине 390 px](../images/pepengine2-ui/chart-review/verified-compact-report.png)

Дальше я бы уплотнил сводку Results. Сейчас дата, длительность и путь к выгруженному ZIP занимают отдельные строки, хотя справа достаточно места. Режим, разрешение, статус и дату можно поставить в одну переносимую строку. Для ZIP достаточно имени файла и действия открытия папки, полный путь можно оставить в подсказке или дать скопировать. При 1280×800 это освободит место для графика уже на первом экране.

## Как это может выглядеть

Три макета сгенерированы в ImageGen по снимкам приложения и отчёта. Числа и кривые на них иллюстрируют компоновку. Оригинальный скриншот показывает, какую часть графика занимала подсказка. [Снимок приложения до исправлений](../images/pepengine2-ui/chart-review/before-native-202c7173.png)

**Увеличенный график.** Одна линия для единиц и команд, свободная область построения, значения и разность на общей базовой линии. Сплошная и пунктирная линии позволяют различать серии и по форме.

![Предложение для увеличенного графика](../images/pepengine2-ui/chart-review/expanded-chart.png)

**Компактный HTML.** На узком экране приоритет у чисел A, B и B−A. Они используют общую правую границу. Справка по жестам открывается по запросу.

![Предложение для компактного отчёта](../images/pepengine2-ui/chart-review/compact-report.png)

**Results.** Переключатель истории у названия сцены, свойства прогона на одной строке, три одинаковые карточки метрик. При таком расположении больше графика видно до первой прокрутки.

![Предложение для заголовка и сводки Results](../images/pepengine2-ui/chart-review/results.png)

## Основа решений

- У PEPEngine2 шрифт Segoe UI, тёмно-зелёные поверхности и лаймовый акцент управления. Для графика уже есть мятная сплошная линия A и янтарный пунктир B. Уместны масштабируемые контурные пиктограммы лупы, разворота, сброса, справки и истории с именем действия. Переключателю единиц нужны видимые текстовые обозначения. [Тема приложения](../../Engine/Engine.UI/src/PepengineTheme.cpp) · [Оформление отчёта](../../Apps/App/Resources/BistroReport.html)
- Carbon рекомендует краткие однозначные легенды, значения обеих координат при чтении точки и свободное от лишних элементов поле построения. Нижняя строка A/B применяет этот принцип к сравнению двух почти совпадающих рядов. [IBM Carbon, Chart anatomy](https://www.carbondesignsystem.com/building-blocks/data-visualization/chart-anatomy)
- У Windows CommandBar основные команды сгруппированы, второстепенные операции раскрываются по запросу, расположение зависит от доступного пространства. [Microsoft, Command bar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/command-bar)
- Для действий, требующих перетаскивания, W3C описывает альтернативу с простым нажатием. Для временно́й шкалы это сдвиг к соседнему участку без мыши или клавиатуры. [W3C, Dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)

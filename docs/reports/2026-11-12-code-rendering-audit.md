# Аудит собственного кода и рендера — 12 ноября 2026

Проверена архитектура собственного кода `Engine`, `Apps` и связанная конфигурация сборки.
Углублённый просмотр: компиляция шейдеров, GPU culling, очереди команд и освобождение
ресурсов, сетка освещения, PBR, прозрачность, отражения, GPU-частицы, вода и skinning.
Выборочно просмотрены render graph, публикация сцены, Jobs/ECS, загрузка mesh cache,
фасад физики и кэш настроек UI. Это прицельный аудит наиболее важных путей,
а не утверждение о проверке каждой строки проекта.

Исходники сторонних библиотек, SDK, импортированные ассеты и их алгоритмы не
аудировались и не исправлялись. При попытке обычной сборки запускались штатные
сборочные шаги зависимостей. Существующие изменения пользователя в
`BistroAdditionsTests.cpp`, `External.Libraries.vcxproj` и подмодулях сохранены.

## Исправлено

### 1. Нестабильные указатели на defines в DXC

`Engine/Engine.RendererDX12/src/GDX12ShaderCompiler.cpp`, `CompileShaderDXC`.

В массив аргументов записывался `storage.back().c_str()`, после чего `storage`
продолжал расти. Перемещение `std::wstring` при перевыделении `std::vector`
делает указатели на внутреннее хранилище коротких строк недействительными.
Несколько коротких defines приводили к ошибке компиляции корректного шейдера.

Теперь сначала собираются все строки, затем их адреса. Публичный интерфейс и
вызывающие проходы сохранены. Дополнительно проверяются HRESULT вызова Compile,
получения статуса и создания выходного blob; необязательный PDB читается только
при наличии результата и имени. Ошибка API больше не ведёт к последующему
разыменованию отсутствующего результата.

Регрессия: `CheckShaderDefines` в `Apps/App/tests/LightingGpuSmoke.cpp` и
`Apps/App/tests/shaders/CompilerDefines.hlsl`. Проверяются восемь коротких defines
и отклонение шейдера без обязательных defines.

### 2. Чтение за границами буфера при преобразовании длинных строк

`Engine/Engine.RendererDX12/Include/Engine.RendererDX12/D3DHelpers.h`,
`StringToWString` / `WStringToString`.

Прежние функции выделяли 512 символов на стеке, не проверяли результат WinAPI и
создавали строку из буфера даже при ошибке. Для строки из 512 символов уже не
помещался завершающий ноль. Это затрагивало аргументы запуска и длинные сообщения
ошибок, включая сообщения об отказе MGPU и подборе качества.

Теперь длина запрашивается у WinAPI, выделяется точный размер и проверяется каждый
вызов. Сохранены CP_ACP и существующая обработка завершающего нуля. Ошибки
преобразования сообщаются через `std::system_error`.

Регрессия: `CheckStringConversions` в `LightingGpuSmoke.cpp`, обе стороны,
длины 0, 1, 511, 512 и 8192.

### 3. Квадратичное уплотнение списка завершённых GPU-команд

`Engine/Engine.RendererDX12/src/GDX12CommandQueue.cpp`, `CollectCompletedLists`.

Удаление каждого завершённого элемента через `vector::erase` отдельно сдвигало
весь оставшийся хвост. При одновременном завершении N списков это давало до
N(N−1)/2 перемещений указателей. Сбор вызывается и при запросе нового command list.

Завершённые списки переносятся одним проходом, затем пустые слоты удаляются
одним `remove` и удалением хвоста. Сохраняются проверка fence с его
идентичностью, порядок повторного использования, незавершённые/записываемые списки
и освобождение удерживаемых владельцев ресурсов. Проход уплотнения теперь O(N).
Это изменение сложности алгоритма; измеренного выигрыша времени кадра нет.

Регрессия: `TestMixedRetirement` в `Apps/App/tests/MGPUQueueTests.cpp`:
32 чередующихся списка, половина завершена, половина ещё записывается,
повторный сбор и проверка порядка повторного использования.

### 4. Выключенные draw-команды попадали в результат GPU culling

`Engine/Engine.RendererDX12/Shaders/Culling.hlsl`, `CS`.

Команды с `InstanceCount == 0` проходили чтение instance/material, проверку frustum
и атомарное добавление в выходной список. Они не рисовали геометрию, но занимали
команды ExecuteIndirect и при включённой группировке проходили дополнительный этап.

Добавлено раннее исключение нулевых команд до чтения instance. Команда загружается
один раз; индекс данных берётся из предназначенного для него `InstanceID`.
Убрана повторная проверка прозрачного слоя после исключения непрозрачного.

Регрессия в `LightingGpuSmoke.cpp` читает оба GPU-счётчика для включённой и
выключенной команды в непрозрачном и прозрачном слоях. Изображение и качество
эффектов намеренно не меняются.

## Приоритеты дальнейшего GPU-профилирования

### 1. Сортировка воды: сотни dispatch и барьеров

`Apps/App/src/Rendering/Water/GDX12Fluid.cpp`, `GDX12FluidSolver::Record`,
и `Apps/App/Shaders/FluidSolver.hlsl`, `Sort`.

Глобальная bitonic-сортировка запускает отдельный dispatch и UAV-барьер для каждой
пары K/J. Для 51 975 частиц ёмкость равна 65 536: 16×17/2 = 136 стадий на подшаг,
408 стадий при трёх подшагах, не считая остальных ядер симуляции.

Это сильный кандидат на уменьшение стоимости записи команд, синхронизации и
обмена с GPU-памятью. Сначала измерить сортировку отдельно от Densities/Integrate
на фиксированном состоянии воды. Затем сравнить сортировку локальных блоков с
глобальным слиянием либо radix-сортировку с полезной нагрузкой. При замене сохранить
порядок частиц с одинаковым ключом либо отдельно проверить влияние изменения
порядка накопления на плотность, энергию и устойчивость симуляции. Без такого
сравнения менять численную симуляцию в рамках общего аудита не стали.

### 2. Прозрачность и forward-материалы перебирают все локальные источники

`Engine/Engine.RendererDX12/Shaders/PBR.hlsli`, `ShadePBR`.

Deferred lighting уже использует frustum light grid. Общий forward-путь вызывает
`ShadeLocalLight` для каждого `LocalLightCount` на фрагмент. Проверка радиуса
отсекает дорогую часть освещения, но чтение источников и сам цикл остаются.
При большом числе локальных источников и перекрывающемся стекле стоимость растёт
с числом источников и слоёв прозрачности.

Измерить отдельно прозрачные проходы и captures. Возможная следующая правка —
использовать существующую сетку света для основного прозрачного вида, сохранив
согласованные координаты вида/глубины; captures требуют своего выбора источников.
Нет данных, что это дороже воды или других эффектов на текущем оборудовании.

## Проверки и ограничения

- Все четыре изменённых C++ translation unit скомпилированы MSVC 14.52:
  `GDX12ShaderCompiler.cpp`, `GDX12CommandQueue.cpp`, `LightingGpuSmoke.cpp`,
  `MGPUQueueTests.cpp`. Использованы пути и определения из compile database,
  адаптированные к текущему checkout/toolset. Это проверка компиляции, не полная сборка.
- `Culling.hlsl` успешно скомпилирован DXC в `cs_6_0` и FXC в `cs_5_1`.
- Отдельный локальный CPU harness исполнил настоящий `CompileShaderDXC`:
  версия до исправления завершилась ошибкой на восьми коротких defines,
  исправленная прошла и корректно отклонила ошибочный шейдер. Harness открывает
  приватный метод только для теста и запрещает обращение к GPU через заглушку
  `GetDeviceFeatures`; обычный выбор shader model устройства этим не проверяется.
- Тот же harness выполнил десять проверок преобразования строк на текущем
  production header: пять длин в обе стороны. Все прошли.
- Полная сборка `LightingGpuTests` не завершилась. MSBuild из VS 2026 не запускается
  из-за несовместимости `System.Memory`. MSBuild из VS 2022 с targets/toolset VS 2026
  проходит дальше, но штатные скрипты FidelityFX/Jolt выбирают CMake, который не
  поддерживает запрошенный генератор `Visual Studio 18 2026`.
- GPU-регрессии culling/очередей добавлены и скомпилированы, но не исполнены.
  Полный Bistro, сравнение изображений, GPU debug-layer прогон, два физических
  адаптера и замер FPS не выполнены. Численного обещания ускорения нет.

В частности, `compile-results.json`, `compiler-smoke.run.log`,

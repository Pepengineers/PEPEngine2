# Исправление assert Jolt на почти вырожденных треугольниках

## Причина

В текущей debug-сессии Rider через MCP установлен точный stop:
`0x80000003`, `EPAPenetrationDepth.h:113`, `JPH_ASSERT(!ioV.IsNearZero())`.
Контакт — convex hull с 32 вершинами против треугольника статической сетки.
`CollideConvexVsTriangles` передаёт в GJK отрицательную нормаль треугольника.

Прочитанные из остановленной сессии вершины в метрах:

```
(0.248607039, -0.976145744, -0.0260321796)
(0.816028357,  0.0451378822, -0.181829929)
(0.541395903, -0.449165344, -0.106423676)
```

Длина максимального ребра — около 1,179 м, высота — 0,49 мкм.
Нормаль практически нулевая. Это объясняет assert; стек worker thread сам
по себе не указывает на ошибку scheduler. Происхождение конкретного sliver
до декодирования сетки не установлено: источник, упрощение и компрессия
не были раздельно сопоставлены для этого индекса.

Встроенный Jolt sanitizer проверяет площадь исходного треугольника и совпадение
вершин после квантования. Почти коллинеарные, но различные вершины могут пройти
эту проверку и получить нестабильную нормаль после компрессии/смены координат.

## Изменение

Фильтр находится в общем Jolt mesh cooker, после применения scale и перевода
в метры, перед `MeshShapeSettings`. Он распространяется также на геометрию
из существующего collision cache; удалять или перестраивать его вручную не нужно.

- Проверяются конечность масштабированных вершин и индексы.
- По bounds используемых вершин оценивается шаг текущего 21-bit codec Jolt
  и погрешность float-координат. Битность берётся из самой библиотеки.
- Треугольники с высотой меньше восьми таких шагов отбрасываются.
- Дополнительно оставлен запас над Jolt cutoff: квадрат нормы cross product
  должен быть больше `16e-12` в физических единицах.
- Число удалённых треугольников пишется один раз при cooking. Если устойчивых
  треугольников не осталось, создание тела завершается ошибкой без assert.

На Bistro фильтр удалил 18 548 Exterior и 392 Interior треугольника,
то есть около 1,27% от 1 490 198 входных collision triangles.
Render mesh и настройки assert Jolt сохранены.

## Проверки

До исправления:

- Новый PhysicsTests case завершился с `Mesh cooker accepted a nearly collinear triangle`.
- Debug BistroPhysicsTests `1 4 3` воспроизвёл **1458** assert'ов на той же
  строке Jolt и завершился с ошибкой. Артефакт: `Build/triangle-sliver-red-Bistro.log`.

BistroPhysicsTests теперь устанавливает test-only обработчик assert, считает
срабатывания атомарно и требует нулевое количество. Ранее production handler
без подключённого debugger только писал ошибку и позволял продолжить тест.

После исправления прошли:

- PhysicsTests Debug/Release, 1/4 worker threads: sliver-only mesh rejection,
  сохранение опоры и разрешимой тонкой поверхности, большой mesh bounds,
  метровые/сантиметровые единицы, NaN rejection; существующие 1000 colliding bodies,
  compounds, scale/cache и fixed pipeline проверки.
- CollisionGeometryTests Debug: примитивы, pivots, отверстия и границы,
  concave chair, зазоры, warm/corrupt cache.
- Debug BistroPhysicsTests: 379 тел, 4 потока, 3 волны/1827 ticks — ноль assert'ов.
- Debug BistroPhysicsTests: 379 тел, 4 потока, 10 волн/4747 ticks — ноль assert'ов.
- Debug BistroPhysicsTests: 758 тел, 16 потоков, 3 волны/1827 ticks — ноль assert'ов.
- Release BistroPhysicsTests: 379 тел, 4 потока, 3 волны/1827 ticks.
- Обычные App Debug/Release пересобраны. Debug-сессия Rider перезапущена через MCP.
  Загруженная сцена работает; повторные MCP observations показывают `running`,
  console не содержит новых exceptions. Assert Jolt остаётся включённым.

Артефакты: `Build/triangle-sliver-green-*.log`,
`Build/triangle-sliver-precision-PhysicsTests-Debug.log`,
`Build/triangle-sliver-long-{1-4-10,2-16-3}.log`.

Это ограниченные прогоны, а не гарантия отсутствия любой будущей ошибки.
Открытые границы Bistro и побеги предметов остаются отдельной проблемой:
отсев slivers не добавляет новых стен или пола.

# DXC-only и минимум SM6 — 12 ноября 2026

Пользователь отменил поддержку SM5.1 и разрешил современные GPU-возможности,
когда они дают пользу. Эта итерация удаляет старый путь компиляции и явно
задаёт минимальное требование. Она не меняет алгоритмы шейдеров или настройки качества.

## Изменения

- `GDX12ShaderCompiler`: удалены CompileShaderFXC и его отдельный include handler.
  Все вызовы CompileShader идут через DXC. Model ниже 6.0 отклоняется до чтения
  исходника; target следует модели адаптера с прежним ограничением SM6.8 для
  поставляемого DXC. Вместо цепочки условий используется номер minor version.
- `GDX12Device::Initialize`: после запроса возможностей адаптер без SM6.0
  освобождается через Reset, возвращается `DXGI_ERROR_UNSUPPORTED`, в лог пишется
  требование и обнаруженная версия. Проверка выполняется **до** регистрации
  primary device в Streamline, создания allocator и очереди. Это сохраняет
  возможность последующей инициализации подходящего primary adapter после отказа.
  Требование применяется также к secondary adapter.
- `InstancingTests`: встроенный D3DCompile/cs_5_0 заменён fixture
  `tests/shaders/ReadVisibleIDs.hlsl` через штатный GDX12ShaderCompiler.
  Root signature, guard пяти элементов и чтение результата сохранены.
- Probe-culling regression в `tools/tests/test_lighting_shaders.py` проверяет
  ClearCS/CullCS через DXC cs_6_0 и cs_6_8. Два остальных contract-теста сохранены.
- В LightingGpuSmoke добавлен отказ компиляции для device без обнаруженной
  поддерживаемой модели. Apps/App/README.md документирует новые требования.

WaveOps и дополнительные возможности остаются под своими capability checks:
SM6 сам по себе не заменяет проверки, необходимые конкретному проходу.
Существующие wave-варианты освещения/частиц сохранены. Новых wave-оптимизаций
без аппаратного сравнения в эту итерацию не добавлено.

`d3dcompiler.lib` не удаляется из общих зависимостей: DXC-wrapper пока использует
`D3DCreateBlob` для существующего интерфейса ID3DBlob. Это выделение blob,
а не компиляция через FXC. Диагностическое имя модели 5.1 сохранено для сообщения
об отказе. Исторические отчёты выполненных FXC-проверок не переписаны.

## Проверки

- Отдельная компиляция MSVC 14.52: GDX12ShaderCompiler.cpp, GDX12Device.cpp,
  LightingGpuSmoke.cpp, InstancingTests.cpp — успешно. После замечания ревьюера
  о Streamline side effect и переноса проверки Device TU скомпилирован повторно.
  InstancingTests сохраняет C4244 из существующего BistroBounds.h:90.
- CPU-проверка точного тела GetShaderTargetForModel, извлечённого из текущего
  исходника: 44 случая stage/model (SM6.0–6.10, ограничение до 6.8), а также
  отказ для 0/5.0/5.1 — успешно. Device feature query в этой проверке mock.
- Пересобранный harness настоящего CompileShaderDXC успешно компилирует fixture
  с восемью defines и отклоняет fixture без обязательных defines. GPU не создаётся.
- CPU-проверка точного префикса Initialize до allocator с mock D3D12/Streamline:
  model 0/5.1 отклоняются до регистрации proxy, созданные handles очищаются,
  последующий model 6.8 регистрируется ровно один раз. Null adapter и ошибка
  D3D12CreateDevice также проверены. Это проверка порядка/ветвления на mocks,
  не выполнение полного Initialize на физических адаптерах.
- `python -m unittest discover -s tools/tests -p test_lighting_shaders.py -v`
  с DXC SDK 10.0.26100.0 — 3/3 успешно, без skip.
- ReadVisibleIDs.hlsl — DXC cs_6_0 и cs_6_8 успешно.
- Поиск в собственных Engine/Apps/tools не находит D3DCompile/CompileShaderFXC
  и исполняемых target cs/vs/ps_5_x. `git diff --check` по файлам итерации прошёл.

Локальные исходники harness, объекты и логи: `Build/DxcOnlyAudit/` (не входят в
коммит), в частности `targets.run.log`, `wrapper.run.log`, `startup.run.log`
и четыре лога компиляции TU. Штатные GPU-регрессии добавлены/перенесены, но в этом
чате не запускались. Полные сборки и GPU-окно принадлежат диагностике/чату воды.

Реальный startup/retry на неподдерживаемом и поддерживаемом GPU, MGPU, полный
GPU smoke и визуальная проверка остаются непроверенными здесь. Нового ускорения
кадра эта итерация не заявляет. Коммит создаёт общий ревьюер после READY/frozen.

# GPU LightGrid в обычном MetaRenderGraph Bistro

Массив локальных источников в обычном Bistro перенесён из прямого чтения UPLOAD
в кадровый DEFAULT/SRV-буфер. Существующий TrackChanges отслеживает данные;
ревизия и идентичность upload-ресурса определяют необходимость загрузки. После
первого заполнения каждого слота статичные источники остаются в VRAM.

`LightGrid.hlsl` строит существующие битовые маски на GPU. Формат потребителя
не меняется: один бит на источник в каждой ячейке, 32 источника на слово. Все
источники могут влиять на одну ячейку без переполнения списка. Размер буфера
зависит от числа ячеек и источников, а не от количества видимых ламп.

По уточнению пользователя скаляризация применена именно к заполнению LightGrid;
обход источников в DeferredLighting не изменён:

- Группа обрабатывает соседние XY-ячейки одного слоя глубины и одного слова
  источников. Цикл не разворачивается, каждый lane держит одну итоговую маску.
- WaveReadLaneFirst делает индекс источника общим для активных lanes перед
  загрузкой и подготовкой его границ. WaveActiveMin/Max вычисляют общие границы
  ячеек wave для раннего отсечения.
- Каждый lane записывает полное слово своей ячейки. Нет InterlockedOr,
  отдельной очистки, CPU-построения масок, копирования масок из RAM и readback.
- Сохраняются консервативные проекции сфер, запас границ, глубинные интервалы,
  последние ячейки и дальний слой CPU-реализации. Общие константы и их валидация
  выделены в BuildLightGridConstants, используемый обоими путями.
- Ресурсы принадлежат кадровым слотам; Meta graph объявляет upload → SRV,
  UAV-построение → SRV-освещение. Волновая ветка выбирается по WaveOps устройства,
  без жёсткого предположения о wave32/wave64; остаётся вариант без intrinsics.

Подход с общим индексом сущности опирается на
[Michal Drobot, Improved Culling for Tiled and Clustered Rendering, SIGGRAPH 2017](https://advances.realtimerendering.com/s2017/2017_Sig_Improved_Culling_final.pdf).
Здесь он адаптирован к генерации масок, а не перенесён вместе со всей архитектурой
рендерера CoD. Исходный production App и диагностический Meta сохраняют CPU-путь.

CPU продолжает задавать небольшие константы камеры/сетки и проверять изменения
источников. Полное отсутствие PCIe-трафика не заявляется: вывод изображения,
команды, константы и работа драйвера остаются вне этой правки.

Выполнена компиляция нового HLSL BuildCS с WaveOps через DXC. Release x64
собран успешно для передачи пользователю. По его инструкции тесты, сравнения масок,
профилирование, замеры occupancy и PCIe, визуальная приёмка не выполняются.
Изменение структуры HLSL не доказывает число аппаратных регистров или ускорение;
это остаётся непроверенным до пользовательской проверки.

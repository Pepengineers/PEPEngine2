# Итог ревью производительности PEPEngine2

Проверена отдельная perf-кампания после исходного rendering review. MGPU-чат по
прямому указанию пользователя оставлен отдельно; его изменения не принимались
и не включались в коммиты этой кампании. Push не выполнялся.

## Где находится ограничение

На принятом snapshot 7acaf950, Ryzen 9 5950X / RTX 4080 SUPER, в стационарном
real-time Bistro наблюдалось преимущественно CPU-ограничение: кадр
21.50–24.18 мс, GPU-интервал 16.80–16.98 мс. На Jolt backend приходится
13.97–16.59 мс CPU wall time, на подготовку/запись рендера 6.77–6.87 мс.
Вложенные scopes не складываются. Эти wall durations включают ожидания и
вытеснение потоков, а не только полезные инструкции движка.

При фиксированных 1200 физических тиках / 20 секундах симуляции кадр составил
18.53 и 22.79 мс, GPU — 16.98 и 16.77 мс. Один запуск близок к границе CPU/GPU,
второй ограничен CPU. Единый GPU-bound вывод для всех сценариев не подтверждён.
XeSS render 985×616, output 1280×800, FG off; это не native/MGPU тест MisSpec.

На GPU основные найденные участки — SPH и тени. Capture использует
time_every_action; его времена служат атрибуции, не сравнению FPS.
Холодная подготовка коллизий локализована в CPU VHACD::Compute.

## Принятые результаты

| Итерация | Решение | Локальный коммит |
|---|---|---|
| CPU/GPU attribution | Принят отчёт с границами инструментирования и внешней нагрузки | f316b8ba |
| Тени | Принята диагностика, production-код и частота обновления не менялись | d19cbf47 |
| SPH | Приняты две строки переназначения потоков по Sorted particle ID, тесты и raw evidence | 45daa504 |
| VHACD startup | Принят диагностический отчёт; guard не перенесён в production | 8f1bf14d |
| Jolt jobs | Принят диагностический отчёт; batch-прототип не перенесён в production | 5dc02b58 |

SPH сравнивался с уже принятой сортировкой B1024: 100980 частиц, три подшага,
120 кадров прогрева, 51 пара в каждом из трёх повторов. Медианы полного solver:
5.117952→1.529856, 5.725184→1.641472, 5.703680→1.536000 мс. Сокращение
70.108%, 71.329%, 73.070%; кандидат быстрее во всех 153 парах. Измерение включает
SavePrevious, Hash/Sort/Offsets/Densities/Integrate и барьеры; CPU submission,
readback и overlap с остальным renderer в него не входят.

Оба particle buffers, density, keys и offsets совпали побитно. Проверены оба
режима физики, неполные группы, совпадающие позиции, production tracked/placed,
завершённые переходы DIRECT→COMPUTE→DIRECT и GPU-based validation. Архивные
Git blobs evidence сверены с SHA-256 manifest; окончания строк сохранены.
Замеры условны для записанной desktop-нагрузки: Editor оставался открыт,
короткий monitor не исключает все GPU bursts. Прирост FPS всей сцены не заявлен.

VHACD-кандидат сохранил 42 cache-файла и прошёл 12 вариантов oracle, но wall
время ухудшилось: 42.98→52.74 и 49.47→61.37 секунды. Снижение CPU-работы и
памяти не заменяет ускорение загрузки. Разные фоновые Git-нагрузки и неразделённые
ожидания внутри Compute не позволяют принять production guard.

Jolt batch-прототип прошёл scheduler/lifetime tests и сравнение FNV-1a-64
хешей/размеров полного SaveState на 1321 тике. Это hash oracle, не побайтовое
сравнение сохранённых state buffers. Две normal fixed-work пары дали
24.2156→19.9325 и 20.7928→19.2023 мс на кадр (−17.69% и −7.65%);
backend — 15.5876→5.0676 и 11.1806→5.0618 мс. Кандидат приблизился к GPU
пределу на старом SPH shader. Total process CPU-time при этом вырос на
10.3% и 9.1%, фоновые Git-нагрузки различались. Третья пара прервана после
minimize baseline, B3 не запускался. Production scheduler оставлен без изменений:
две пары не заменяют согласованный gate из трёх и ordinary real-time проверку.
Ревьюер повторно сверил 195 evidence SHA-256 и offline-анализ четырёх runs;
в каждом 1200 measured frames/ticks, 20 simulated seconds, debt=0.

## Общие ограничения

Нулевое число обнаруженных компиляторов не доказывает отсутствие всех внешних
нагрузок. Фоновые Git scans и пользовательские приложения не останавливались.
Их влияние учитывается по доступным process timelines, без недоказанной причинной
атрибуции. Shared MGPU files сохранены, сборки/GPU-запуски наших чатов сериализованы.

Отдельно найдено ограничение benchmark при сворачивании собственного окна:
client area 0×0 даёт бесконечный projection._11; light-grid guard корректно
останавливает рендер. Это не исправлялось внутри scheduler-эксперимента.

Общий эффект SPH вместе с другими оптимизациями на текущем изменяющемся HEAD,
полный visual A/B, длительный soak и другая физическая GPU этой кампанией не
подтверждены. Подробности:

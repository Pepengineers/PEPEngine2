# Пакетное копирование локальных теней: Debug и Release

Дата: 2026-11-04. База — `383ddcc` после завершения merge main.
Продолжение [диагностики низкой загрузки GPU в Debug](2026-11-04-debug-gpu-utilization.md).

На этой машине медианное время полного кадра без профайлера сократилось
**57,50 → 49,95 мс в Debug** и **26,09 → 24,93 мс в Release**.
PIX подтверждает уменьшение CPU-записи команд, Nsight — GPU-времени локальных
теней и количества barrier ranges. GPU-readback тесты проходят в обеих конфигурациях.

## Изменение

`GDX12LocalShadowPass::Execute` сначала обновляет статический кэш, затем копирует
все dirty slices в динамический массив и только после этого записывает draw/cull
для этих граней. Для непустого обновления массив назначения переводится в
COPY_DEST и DEPTH_WRITE один раз, вместо переключений для каждой грани.
Порядок отдельных draw/cull, visibility buffers и правила dirty/cache сохранены.
Если dirty faces нет, копирование и дополнительные depth transitions пропускаются.

Сохранены первоначальная очистка всех slices, итоговое SRV-состояние, обновление
отдельных граней, EveryFrame, инвалидация статического кэша и static-only capture
для reflection probes. Новых CVars, ресурсов и зависимостей нет.

## Проверка корректности

Обе конфигурации x64 собраны с `PEPEnableProfiling=true`, чтобы PIX/Nsight видели
одинаковые CPU/GPU-маркеры. Baseline и optimized EXE/PDB/runtime сохранены отдельно.
Во время замеров компиляция и другие тестовые GPU-процессы не запускались.

`LightingGpuTests` и `ReflectionProbeTests --debug` прошли в Debug и Release.
Тесты используют D3D12 debug layer и фактический GPU readback. Проверены:

- Статические и динамические point/spot shadows, первый bake, пустое обновление,
  EveryFrame, смена владельца slice, удаление/перенос caster и переход между faces.
- Дополнительно проверено, что point/spot depth остаётся заполненным после
  пустого обновления, изменения только spot, перерисовки шести point faces и
  общей инвалидации статического кэша.
- Depth/radiance reflection probes, публикация кэша, roughness, parallax,
  переключения runtime и статические локальные тени внутри capture.

В этих проверках D3D12 errors не обнаружены. GPU-based validation отдельно
не включалась (`--debug` в probe-тесте оставляет обычный debug layer).

## Метод измерений

Артефакты: `Build/Captures/2026-11-04-shadow-copy-batch/`.
`build.ps1`, `measure.ps1`, `analyze-pix.py`, `capture-nsight.mjs` и `summarize.py`
содержат команды и проверки результатов. `*-hashes.json` фиксируют EXE/PDB/INI,
`shader-manifest.json` — используемые HLSL.

RTX 3060 Laptop, Bistro, стартовая камера 1280×800, XeSS, 250000 частиц,
`Render.NumFrames=3`, defaults остальных CVars. Все четыре runtime INI идентичны.
Исходники шейдеров одинаковы; между вариантами изменён только порядок копирования
и переходов в локальных тенях. Debug сохраняет штатный D3D12 debug layer;
Release приложения его не включает.

### PIX Timing при обычных частотах

По одному независимому прогретому процессу на вариант/конфигурацию, 40 секунд
до подключения PIX, запись 8 секунд, sampling 1000/s. Анализ CPU: окно 1000–7000 мс,
только полные экземпляры правильных processId/eventId, без пустых строк PIX.
Lost ETW events/buffers = 0 во всех четырёх captures.

| Медиана, мс | Debug baseline | Debug optimized | Release baseline | Release optimized |
| --- | ---: | ---: | ---: | ---: |
| CPU frame interval | 58,785 | 51,552 | 26,061 | 24,680 |
| Graph recording | 40,973 | 33,459 | 5,418 | 4,846 |
| GPU command-list envelope | 25,774 | 24,658 | 26,125 | 24,581 |
| Промежуток между GPU-пакетами | 33,062 | 27,139 | 0,101 | 0,101 |

В Debug запись команд сократилась примерно на 18,3%, CPU frame interval — на
12,3%. В Release запись команд сократилась примерно на 10,5%, frame interval —
на 5,3%; графическая очередь в обоих Release-окнах практически непрерывно занята.

GPU-envelope/gap рассчитаны в окне 1000–2000 мс по фактическим work items самой
занятой графической очереди приложения, группировкой `executionId` и
`commandListIndex`. Это оболочки пакетов с внутренними паузами, а не shader-only
timing или глобальный аппаратный utilisation counter. Неполные граничные
пакеты не входят в медиану длительности. Сумма оболочек занимает соответственно
43,91% / 47,76% окна Debug и 99,62% / 99,60% окна Release.

### Повторные запуски без профайлера

По три независимых процесса для каждого варианта/конфигурации, с чередованием
baseline/optimized. Встроенный benchmark исключает начальную загрузку и первый
кадр, затем измеряет 600 кадров с завершающим ожиданием GPU. Здесь учитывается
весь кадр, а не только проход теней.

| Вариант | Запуск 1, мс | Запуск 2, мс | Запуск 3, мс | Медиана, мс |
| --- | ---: | ---: | ---: | ---: |
| Debug baseline | 56,5430 | 57,4967 | 57,9558 | **57,4967** |
| Debug optimized | 49,0775 | 52,4766 | 49,9493 | **49,9493** |
| Release baseline | 25,9986 | 26,0941 | 26,3955 | **26,0941** |
| Release optimized | 24,8101 | 24,9307 | 25,0328 | **24,9307** |

Время кадра по медиане уменьшилось на **13,13% в Debug** и **4,46% в Release**.
Эквивалентный рост FPS — **15,11%** и **4,67%** соответственно.
Все три optimized результата быстрее всех трёх baseline результатов своей
конфигурации. Это измерение данной машины и сцены, не гарантия для других GPU.

### Nsight GPU Trace

Nsight Graphics 2026.4, native GTAPI, Top-Level Triage, trigger frame 180,
12 кадров на процесс, PM bandwidth 1000, PC sampling выключен. GPC frequency
во всех четырёх трассах — 900 МГц. Это отдельное измерение с base clocks,
его frame time не используется как обычный FPS.

| Метрика | Debug baseline | Debug optimized | Release baseline | Release optimized |
| --- | ---: | ---: | ---: | ---: |
| Local shadows, среднее мс/кадр | **17,413** | **15,236** | **16,567** | **14,885** |
| Полный GPU trace, среднее мс/кадр | 44,894 | 43,013 | 44,276 | 41,760 |
| Обновлённые shadow views, за 12 кадров | 2491 | 2479 | 2441 | 2507 |
| `Local shadow copy` marker instances | 2491 | **12** | 2441 | **12** |
| Barrier ranges графической очереди | 24925 | 22386 | 24575 | 22554 |
| GR Engine Active, % | 96,94 | 97,89 | 97,37 | 97,94 |

Среднее GPU-время прохода теней сократилось на **12,50% в Debug** и **10,16% в
Release**. Вместо чередования копирования и рисования для каждой грани теперь
есть одна группа копирования на кадр. Количество скопированных граней не
сокращалось алгоритмом: различия views между трассами происходят из продолжающейся
симуляции. В Release optimized обработано даже на 2,7% больше views.

`barrier_count` здесь — число ranges, которое возвращает GTAPI для очереди,
не число отдельных subresources или всех физических аппаратных барьеров.
Снижение количества ranges согласуется с устранением повторных вызовов
перехода массива в COPY_DEST. Видимый эффект подтверждён независимо CPU timings
в PIX и повторными normal benchmarks.

Overflow warnings нет. Единственное предупреждение в каждой трассе — удалённые
недоступные per-shader metrics; они не использованы. Time Every Action выключен,
поэтому per-action timestamps не трактуются как точные времена отдельных draws.
Whole-pass scopes, длительность окна, view/marker counts и общие counters сохранены
в `*-analysis.json`; итоговое сравнение — `comparison.json`.

## Границы выводов

- Анимация, частицы и движущиеся props продолжают симуляцию. Одинаковый номер
  кадра не гарантирует одинаковый wall-clock момент и состояние сцены. Поэтому
  normal benchmark повторён, а timings отдельных проходов рассматриваются
  вместе с числом обновлённых граней и очередями.
- PIX-замеры и обычный benchmark не смешиваются с Nsight, который фиксирует
  GPU clocks на base. Рост FPS не обязан сопровождаться ростом процента загрузки
  GPU: оптимизация одновременно сокращает работу CPU и GPU.
- При сборке остались предупреждения сторонних библиотек/PDB, включая LNK4099
  и LNK4020. Для основных выводов используются именованные runtime scopes и
  аппаратная timeline, а не полнота Release type symbols.
- Другие GPU, длительный soak и произвольные пользовательские сцены не проверены.

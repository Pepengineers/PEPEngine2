# U12 Integrated acceptance and delivery - Plan

## Contract

Выполнить только U12 из [мета-задания](00-meta-plan.md), проверить R1–R14 и Definition of Done. Требуется принятый U11 и отчёты всех предыдущих этапов. Этот этап не разрешает переключить основной App или удалить старый граф.

## Outcome

Воспроизводимо проверенное дополнительное приложение с новым execution plan, hierarchical CPU recording, same-GPU async и independent MGPU воды/частиц. Все необходимые исправления обнаруженных регрессий включены; итог честно отделяет подтверждённое от аппаратно недоступного.

## Files

Существующий executable/fixture для обычного запуска; исправления только по выявленным дефектам. `docs/reports/meta-render-graph/12-acceptance.md`, финальный `technique-inventory.md`, руководство запуска `Apps/App.MetaRenderGraph/README.md`.

## Approach

1. По коду и отчётам сверить подключение техник к новому executor. Отметить реально отсутствующие части.
2. Использовать уже полученные результаты запуска; если результата нет и запуск разрешён, выполнить один короткий smoke итоговой сцены.
3. Исправить обнаруженные явные ошибки работы в owning stage.
4. Подготовить краткое руководство запуска и итоговый статус. Production App остаётся на прежнем executor.

## Smoke-check

Применяется [общий порядок проверки](00-meta-plan.md#verification-contract). Итоговая сцена запускается на выбранной конфигурации, GPU выполняет работу, результат отображается. Достаточно обычного короткого запуска без явных ошибок; уже полученный результат можно использовать повторно без нового прогона.

## Acceptance and Handoff

Обновить инвентарь и README с запуском, выбором адаптеров и известными ограничениями. Кратко записать commit, выбранный режим и итог: работает / не работает / не запускалось, с причиной при наличии. Локальный коммит только своих изменений. Переключение основного App и удаление старого графа требуют отдельного задания.

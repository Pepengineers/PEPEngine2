# Vertex Fetch для большой липы Bistro

Для ствола и листвы большой липы Bistro используем неиндексированный вызов отрисовки без привязанных вершинного и индексного буферов. Вершинный шейдер по `SV_VertexID` читает индекс из SRV, затем по индексу читает атрибуты вершины из SRV. Так исходная геометрия сохраняет общие вершины, а отрисовка может отдельно читать результат симуляции ветра, которую в будущем планируется перенести на второй адаптер.

## Ветер и отклик кроны

Трава и липа используют общие настройки ветра Bistro. При лёгком ветре ствол и крупные ветви неподвижны, порыв последовательно отклоняет участки кроны, а мелкие фрагменты листвы колеблются с разными фазами. Основа такого разделения движения по масштабу описана у [Renaldas Zioma](https://developer.nvidia.com/gpugems/gpugems3/part-i-geometry/chapter-6-gpu-generated-procedural-wind-animations-trees) и [Tiago Sousa](https://developer.nvidia.com/gpugems/gpugems3/part-iii-rendering/chapter-16-vegetation-procedural-animation-and-shading-crysis).

Отклик кроны и деформацию вершин рассчитываем в compute. Разделяем их по выходным данным, чтобы граф мог планировать работу на асинхронной очереди, а при дальнейшем переносе на другой адаптер можно было выбрать, какой результат передавать.

У липы своё поле ветра в границах кроны. Настройки и время порывов общие с травой, поэтому выключение отрисовки газонов сохраняет ветер на площади. Графика использует позу предыдущего кадра, пока compute готовит следующую. Проходы глубины, теней и цвета читают одну позу, а для векторов движения доступна также предыдущая показанная поза.

## Геометрия и замеры

На площади загружаются два авторских LOD [липы Georgeous](../../Assets/Models/GeorgeousLinden/LICENSE.md). Оба используют одно преобразование, привязанное к основанию ствола исходной липы Bistro. В F1 параметр `Render.Tree.Quality` выбирает Low (0, LOD1) или High (1, LOD0, по умолчанию). Ветер, позы и отрисовка работают с выбранным мешем. При переключении история поз начинается заново, поскольку топологии различаются.

Для сравнения GPU-времени в PIX у проходов `linden LOD0` и `linden LOD1` есть отдельные события `evaluate crown and flutter` и `deform next pose`. Сравнивать следует установившиеся кадры при одинаковом ветре, пропуская кадр смены LOD с загрузкой буферов. Количество вершин, треугольников и фрагментов обоих уровней выводится при загрузке Bistro.

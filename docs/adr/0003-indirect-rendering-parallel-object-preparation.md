# ExecuteIndirect с параллельной подготовкой данных объектов

Сохраняем GPU-driven ExecuteIndirect; отдельный CPU draw-путь не добавляем. Распараллеливаем обновление ECS и подготовку данных объектов, включая исходные записи indirect-аргументов там, где требуется их построение или изменение. Это использует имеющуюся GPU-фильтрацию видимости и не заменяет один ExecuteIndirect множеством CPU draw-вызовов ради загрузки workers.

Исходный набор кандидатов общий для камеры и теневых представлений, но каждое представление независимо отбирает видимые записи на GPU. Пользователь отдельно включил ExecuteIndirect для теней в требование; текущий код уже содержит этот путь для каскадов солнца и point/spot-теней, поэтому нужно сохранить его и проверить динамическое обновление при движении предметов.

Параллельная подготовка данных не требует параллельной записи DX12 command lists: workers заполняют непересекающиеся диапазоны заранее выделенных CPU/GPU-visible данных, а запись существующих проходов остаётся последовательной. Полный per-list resource-state tracker и отдельный CPU renderer не входят в первую версию.

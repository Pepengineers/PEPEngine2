# Компонентные техники сцены

Перечень по `WorldECS`, сбору данных в `RenderModule` и настройке Bistro, 2026-11-04.
Это список реализованных техник, которые устанавливаются на объекты сцены.

| Техника | Компонент / точка подключения | Bistro |
|---|---|---|
| GPU-частицы | `ParticleEmitterComponent` + `TransformComponent` | Восемь эффектов, общий бюджет 250000 |
| Трава | `GrassRenderComponent` | Один участок у входа, `App.Grass.Count` |
| Поле ветра | `WindFieldComponent`, ссылка из травы | Аналитический ветер для каждого участка травы |
| SPH-жидкость и поверхность воды | `FluidRenderComponent` | Один небольшой бассейн, `App.Water.Count` |
| Скелетная анимация / GPU skinning | `SkeletalMeshRenderComponent` | Четыре человека снаружи и одна лиса внутри, `App.NPC.Count` / `App.Fox.Count` |
| Локальные отражения из cubemap | `ReflectionProbeComponent` | Четыре frozen static кубмапы, `App.ReflectionProbes.Count` |
| Текстурное небо / IBL | `SkyBoxComponent`, выбор через `World::SetSkySource` | Есть на Sun |
| Физическая атмосфера / IBL | `SkyAtmosphereComponent` | Не выбрана |
| Процедурные 2D-облака | Renderer-компонент `GDX12CloudComponent`, `GDX12EnvironmentIBLPass::SetCloudSource` (отдельного ECS-компонента нет) | Не подключены |
| Направленный, точечный и прожекторный свет с тенями | `LightComponent` | Sun и светильники Bistro |

Статические меши, материалы и прозрачность — базовые `StaticMeshRenderComponent`.
Отбрасывание теней отдельного меша управляется `StaticMeshRenderComponent::CastsShadows`
или `SkeletalMeshRenderComponent::SetCastsShadows(bool)`, по умолчанию включено.
Для static mesh тот же `CastsShadows` читается из YAML. Переключение обновляет
sun/local shadows и тени внутри reflection capture, сохраняя видимость объекта
и получение освещения. Preview-сферы Bistro используют opaque-материал собственной
cubemap и явно выключают отбрасывание теней.
Камера, transform, velocity, spline/circle/look-at и локальный `FlyingPropComponent`
управляют сценой, но не являются отдельными графическими эффектами.
AO (SSAO/HBAO/XeGTAO/CACAO), SSSR, DoF, motion blur, depth prepass,
тональная компрессия и реконструкция изображения — общие проходы кадра.

## Установленные эффекты частиц

`Apps/App/src/BistroScene.h` устанавливает восемь независимых эмиттеров.
Искры используют additive HDR; пыль и пар — weighted alpha. Часть эффектов
использует огненный атлас, искры и пыль — аналитические диски. Светлячки используют
объёмную модель из 120 вершин и 40 треугольников: голова, корпус, светящееся
брюшко и два машущих крыла. Это один общий vertex buffer с GPU-инстансингом,
без GS; модель создаётся в `GetFireflyParticleMesh`, а не разворачивается в спрайт.

| Эмиттер | Эффект | Положение, см | Частиц при 250000 |
|---|---|---|---:|
| `BistroEntranceFountain` | Золотой фонтан у входа | (-170,45,-170) | 62500 |
| `BistroBlueFountain` | Голубой фонтан с другой стороны двери | (-70,45,65) | 46875 |
| `BistroTerraceEmbers` | Тлеющие искры над террасой | (-480,65,-430) | 31250 |
| `BistroPlanterFireflies` | Mesh-светлячки около растений, 6–10 см | (-420,110,150) | 31250 |
| `BistroStreetFirebursts` | Расходящиеся огненные вспышки | (-350,90,-700) | 31250 |
| `BistroInteriorDust` | Медленная пыль в интерьере | (160,180,-160) | 15625 |
| `BistroTableSteam` | Восходящий пар | (550,130,-350) | 15625 |
| `BistroSparkRain` | Падающие розовые искры | (-650,300,-120) | 15625 |

App-CVar `App.Particles.CountScale` имеет default **1** и runtime-запись.
Она домножает авторские количества: **1** = 250000, **4** = 1000000,
**1.25** = 312500, **0.6** = 150000, **0.5** = 125000. Все положительные дробные
множители используются напрямую. Только при **<=0** используется множитель **1**, а не отключение.
Верхний предел — 4194304/250000, нефинитные значения отклоняются.
Выключение всех частиц остаётся за `Render.Particles.Enabled`. Распределение
4:3:2:2:2:1:1:1 сохраняется; округление по накопленным долям гарантирует точную
сумму даже для бюджета 1 или 7. Суммарный масштабированный бюджет округляется
до ближайшего целого. При множителе 4 каждый эмиттер получает ровно ×4.
Пулы не превышают индивидуальный предел 1048576. Эта CVar зарегистрирована
только в Bistro App и тестах, подключающих его настройку сцены.

Бюджет означает живые симулируемые частицы, а не только резерв памяти. App при
создании и перед каждым render запрашивает refill до вместимости каждого пула.
Существующий GPU spawn принимает только свободные слоты после смерти частиц;
CPU не считывает счётчики и не создаёт частицы по одной. С первого активного
GPU-кадра поддерживается заданное число, в том числе после истечения жизни.
Отрисованных частиц может быть меньше из-за frustum/depth/size/alpha culling.
Пауза мира/компонента замораживает симуляцию. Global Off сохраняет обычную
семантику renderer. Изменение бюджета пересоздаёт затронутые пулы с GPU flush
и сбрасывает их живое состояние; такие кадры нужно исключать из FPS-замера.

Для запуска и бенчмарка:

```powershell
.\Build\bin\x64\Release\App\App.exe -App.Particles.CountScale=4
.\Build\bin\x64\Release\App\App.exe -App.Particles.CountScale=1 -Loading.BenchmarkOutput=Build/particles-250k.json -Loading.BenchmarkFrames=121
```

Также можно записать `App.Particles.CountScale = 4` в секцию `[ConsoleVariables]`
файла `Config/Engine.ini` рядом с **App.exe** или вызвать `SetFromString` во время
работы. Аргумент CLI имеет приоритет над INI. Не добавлять App-CVar в общий INI
других приложений/тестов, которые её не регистрируют. JSON измерения содержит
`particle_count_scale` и фактический `particle_budget` рядом с существующими counters.

Размеры частиц увеличены: фонтаны 7.5→2 см, тлеющие искры 4→1 см,
вспышки 12→25 см, пыль 1.8→0.5 см, пар 4→16 см, дождь искр 3→1 см.
Mesh-светлячки имеют корпус, отдельные крылья, мировую ориентацию и нормали,
а также движение вершин в motion target. Они используют weighted alpha и
стилизованное освещение с эмиссией брюшка; теней/PBR и самостоятельного depth
write нет, как и у остальных прозрачных частиц.

Атлас: `Assets/Textures/Particles/mgpu-fountain-atlas.png`, 8×8 кадров из
MGPU, один проход за жизнь частицы. [Происхождение](../../Assets/Textures/Particles/README.md).

Коллизия включена на обоих фонтанах, огненных вспышках и дожде искр. Симуляция восстанавливает поверхность
и нормаль из текущей jittered reverse-Z глубины, проверяет пересечение на каждом
подшаге, выталкивает частицу на радиус и отражает входящую скорость с restitution.
Чтение depth выполняется как compute SRV до dispatch. Параметры принадлежат
эмиттеру, по умолчанию коллизия выключена для остальных компонентов.

Это экранная коллизия: видна только ближайшая поверхность текущего depth buffer
(в том числе слитая глубина воды). За кадром, за непрозрачной геометрией, в
прозрачном стекле без записи глубины и на тонких силуэтах столкновение не гарантируется.
Полного физического collider/scene query здесь нет.

## Проверка

Release/x64: `App`, `BistroPropsTests`, `BistroStartupTests` и `SecondGroupTests` собраны MSBuild 18,
`PreferredToolArchitecture=x64`, `/m:1 /nr:false`, `_CL_=/Z7 /GL-`.
Оставлены существующие предупреждения компилятора и LNK4099 сторонних библиотек.

`SecondGroupTests` проверяет GPU spawn/indirect, три режима смешивания, reset/removal
и коллизию с независимой плоскостью глубины: Off пропускает частицу за плоскость,
restitution=1 отражает её, restitution=0 останавливает на радиусе. Проверяются
пиксели и глубина через GPU readback. Прогон проходит с debug layer и GBV.

`BistroStartupTests` проверяет восемь эмиттеров, реальный atlas SRV, координаты,
включённую коллизию, сохранение 346 props, runtime-множители 1/4/0.5/<=0
и 90 кадров Bistro с debug layer. `BistroPropsTests` проверяет точные суммы,
масштабирование ×4, крайние значения, округление, паузу и отказ невалидным CVar.
GPU refill fixture в `SecondGroupTests` проверяет 250k/1M живых частиц через
R32F alpha accumulation/readback с первого кадра и после одновременной смерти.
Все эти проверки прошли; GPU refill также прошёл с GBV без ошибок debug layer.
Предыдущие проверки абсолютного бюджета сохранены в `Build/BistroParticleBudget`;
новый интерфейс CountScale проверяется в `Build/ParticleMeshes`. CPU-проверки
охватывают дроби, fallback <=0, верхний предел, геометрию/нормали и размер модели.
GPU pipeline statistics проверяют 40 треугольников на инстанс в цвете и motion,
а также **нулевое число вызовов GS** для weighted/additive mesh-частиц.
Эти проверки прошли вместе с GBV и 90 кадрами реальной Bistro без ошибок debug layer.
CLI-прогоны CountScale 0/-2/0.5/4 подтвердили бюджеты 250000/250000/125000/1000000;
17 отклоняется без диалога. Увеличенные эффекты осмотрены в App; снимок —
`Build/ParticleMeshes/larger-effects.png`. Это визуальная проверка, не замер FPS.
Внешний вид эффектов осмотрен в App при 250000; снимок —
`Build/BistroParticleBudget/effects-250k.png`.

Первоначальная проверка фонтана выявила и закрыла ошибку учёта состояния загруженных текстур:
`RenderModule::CreateDX12Texture` теперь сохраняет в обёртке реальное состояние SRV,
установленное upload-командами. Логи: `Build/BistroParticles`.
Окончательный фонтан осмотрен из стартовой камеры; снимок —
`Build/BistroParticles/fountain.png`.

Длительный stress test и физические столкновения за пределами depth buffer
не проверялись и не добавлялись.

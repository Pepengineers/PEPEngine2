# MGPU: размещение техник и ручные настройки

Одна модель зависимостей описывает проходы на основном и дополнительном GPU и очередях Direct, Compute и Copy. Постоянный исполнитель выдаёт реальные fence points; зависимые очереди ждут нужное значение fence на GPU. Фоновый producer может запускаться независимо от кадра. Контракты: [очереди и граф](../adr/0011-mgpu-logical-graph-and-device-queues.md), [версии, свежесть и частота](../adr/0012-mgpu-snapshot-freshness-and-cadence.md).

## Включение

Все MGPU enable-переключатели в исходниках и `Config/Engine.ini` по умолчанию `false`. Для эксперимента задайте `Render.MGPU.Enabled=true` **до запуска** и включите нужную технику. `Render.MGPU.SecondaryLuid=0` выбирает первый пригодный другой аппаратный адаптер; ненулевое значение — его packed unsigned decimal LUID. Оба параметра runtime читаются при старте. Отсутствие подходящего адаптера оставляет основной GPU с диагностикой причины.

Настройки профиля платформы задаются вручную через CVars/INI. Автоподбор GPU, частоты и качества, а также измерение ускорения относятся к [следующему этапу бенчмарков](../plans/2026-11-09-quality-presets-benchmark-plan.md).

| Техника | Включение на втором GPU | Режим и дополнительные параметры |
|---|---|---|
| Вода | `Render.Fluid.MultiGPU=true` | `Render.Fluid.MultiGPU.Exact`: `false` — Latest, `true` — Exact; `.UpdateHz`, `.MaxAgeMs`. Смена размещения применяется при следующей эпохе симуляции. |
| Поля травы | `Render.Grass.MultiGPU=true` | `Render.Grass.MultiGPU.Exact`, `.UpdateHz`, `.MaxAgeMs`. Analytic и ProjectedGrid; основной GPU разворачивает геометрию. Grass и Firefly используют одну выбранную версию поля. |
| Облака и окружение | `Render.Clouds.Bistro=true`, `Render.Clouds.MultiGPU=true` | `Render.Clouds.Latest=true` — Latest, `false` — Exact; `.UpdateHz`, `.MaxAgeMs`. `Render.Clouds.AsyncCompute` выбирает локальную Compute-очередь при локальном размещении. |
| AO | `Render.AO.MultiGPU=true` | Exact текущего кадра. `Render.AO.Resolution=0` — полное разрешение, `1` — половина каждой оси с полноразмерным выходом visibility. Работает с четырьмя существующими алгоритмами и обеими позициями AO. |
| Тени | `Render.Shadows.MultiGPU=true` | Exact, отбор через `Render.Shadows.MultiGPU.Selection` и `.Entity`, см. ниже. |
| UI | `Render.UI.Offload=true` | `Render.UI.OffloadScope`, `.CanvasId`, `.Freshness`, `.UpdateHz`, `.MaxAgeMs`, `.Quality`, см. ниже. |

`UpdateHz=0` не ограничивает частоту producer; положительное значение ограничивает запуски согласно политике техники. Это не изменение скорости игрового времени. `MaxAgeMs=0` отключает порог диагностики возраста.

## Exact и Latest

**Exact** требует конкретную версию результата и ставит зависимости перед её потребителями. **Latest** выбирает только полностью завершённый импорт на основном GPU. Незавершённая запись в общий ресурс не становится доступным снимком.

Latest может повторять совместимый старый снимок. При превышении `MaxAgeMs` он продолжает отображаться, а состояние техники сообщает превышение возраста. Качество, скорость сцены и частота остальных техник автоматически не меняются. Изменение несовместимого содержимого, размера или эпохи инвалидирует старый снимок; поведение локального восстановления определяется техникой. Очереди публикаций и хранилища ограничены; вода и трава учитывают накопленные входы и долг симуляции.

Стабильные 55 обновлений producer при 60 кадрах рендера — допустимый ручной профиль, если визуальная задержка приемлема на выбранной платформе. Это не гарантия ускорения: передача данных и конкуренция за одну очередь тоже стоят времени. Latest не меняет FIFO-порядок уже отправленных команд; длительный compute-проход может задержать следующую строгую задачу на той же очереди.

## Тени

`Render.Shadows.MultiGPU.Selection`:

| Значение | Выбор |
|---|---|
| `0` | Солнце и все локальные источники |
| `1` | Только солнце |
| `2` | Все локальные источники |
| `3` | Один локальный источник: ECS slot из `Render.Shadows.MultiGPU.Entity`, разрешённый в актуальный handle с generation |

Передаются полные группы: четыре каскада солнца, шесть граней point light или одна карта spot light. Невыбранные карты сохраняют локальный путь. Результат восстанавливается в основной shadow atlas, которым пользуются существующие потребители. Если нельзя воспроизвести полный набор casters, вся соответствующая группа остаётся локальной.

Реплика сцены включает статические меши, skinning по замороженным палитрам и alpha-mask textures. Трава для удалённых теней разворачивается на втором GPU из того же выбранного поля, что используется основным кадром; это работает и при локальном расчёте поля травы. У статического atlas для probes сохраняется отдельная семантика.

## Экранный UI и плакаты

`Render.UI.OffloadScope=0` выбирает экранный UI и обе world-space поверхности. Значение `1` выбирает только `Render.UI.CanvasId`: `1` — ATRIUM, `2` — TERRACE. Экран и другая поверхность в этом случае остаются локальными. Неизвестный CanvasId не выбирает поверхность и даёт диагностируемый локальный путь.

Экранный UI всегда Exact. `Render.UI.Freshness=0` задаёт Exact для плакатов, `1` — Latest. В Exact пропущенный из-за cadence запуск использует локальный кадр с той же фазой. `Render.UI.AsyncCompute=true` разрешает локальный Compute для эффектов плакатов.

`Render.UI.Quality=0` — Low, `1` — Medium. Medium повышает растровое разрешение, число анимированных элементов и радиус blur; обе градации используют одни часы анимации. Это ручная ось нагрузки для будущего сравнения размещений. Плакаты являются материалами двух поверхностей Bistro; ввод и hit testing в 3D не реализуются. Экранный UI сохраняет свой ввод.

## Проверка результата

В Debug откройте F1. Панель Debug controls показывает запрошенное и активное размещение за последний кадр, режим Exact или Latest и причину перехода на primary. При наличии снимка она показывает возраст и отмечает превышение порога как OVER AGE.

Совместная проверка Bistro прошла в Debug со всеми шестью техниками. Два интегрированных сценария GBV на полной сцене прошли с Sun-only и с одним выбранным Point. Полный GBV с переносом всех теней остановлен на пороге системного commit. [Отчёт и артефакты проверки](../reports/2026-11-10-mgpu-bistro-production.md)

Для сравнения изображений сохраняйте одинаковые входы, время, seed, качество и разрешение. Передача и replay на одном адаптере проверяются строго. Между производителями GPU некоторые вычислительные шейдеры дают численные различия; допуски AO и окружения документированы в соответствующих отчётах и не являются универсальной гарантией эквивалентности изображений.

Сборки, проверки D3D12/GBV, capture и будущие performance-прогоны выполняются последовательно одним владельцем GPU-слота. Производительность не следует из прохождения correctness-проверок.

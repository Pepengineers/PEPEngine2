# Логирование

Подключите `Engine.Core/Logging/Logger.h`:

```cpp
Log::Info("Loading", "Importing ", sourcePath);
Log::Warning("Texture", "Using a fallback for ", texturePath);
Log::Error("Shader", "Compilation failed: ", shaderPath, " [", entryPoint, ']');
```

Аргументы перечисляются через запятую; не нужно заранее собирать строку через `+`, `to_string` или поток. Поддерживаются числа, строки UTF-8, `std::wstring`, string_view, файловые пути и копируемые типы с `operator<<`. Строковые представления и C-строки копируются: временные строки не остаются висячими ссылками. Пользовательский тип должен быть безопасен для форматирования на другом потоке; не передавайте `std::ref` или указатели на изменяемые объекты.

Каждая строка содержит время UTC с миллисекундами, уровень, категорию и ID потока-источника:

```text
2026-11-01T00:10:42.107Z [INFO] [Loading] [thread 1234] Importing scene.obj
```

Путь по умолчанию — `Logs/Engine.log` рядом с exe. Существующий файл дополняется. `Logger::Get().GetPath()` возвращает фактический путь; отдельный `Logger(path)` создаёт независимый экземпляр, например для инструмента или теста.

Вызывающий поток только копирует аргументы в очередь под короткой блокировкой. Разбор аргументов для вывода, конвертация UTF-16 в UTF-8, форматирование времени, создание каталогов, открытие файла, запись и сброс буфера выполняются одним фоновым потоком. Создание глобального логгера один раз запускает этот поток. Несколько потоков могут писать одновременно; принятые записи сохраняются в порядке помещения в очередь и не перемешиваются внутри процесса.

`Log::Flush()` явно ждёт записи всех сообщений, принятых до вызова, и возвращает успех/ошибку. Он нужен перед аварийным завершением; при обычном выходе деструктор логгера сам дописывает очередь и завершает поток. Обычные `Info/Warning/Error` не ждут диска и возвращают, принята ли запись. Ошибка открытия/записи переводит экземпляр в состояние отказа, будит ожидающий `Flush()` и сообщается в stderr/отладчик; последующие сообщения отклоняются.

Ошибка INI сначала попадает в общий логгер, затем `Flush()` гарантирует её запись до выброса `ConsoleConfigError`. Обработчики остальных исключений приложения также сохраняют диагностику перед завершением. `Error()` сам по себе приложение не закрывает.

`Log::Info/Warning/Error` не выбрасывают исключений в вызывающий код. Если не удалось запустить логгер или скопировать аргумент, запись возвращает `false`; критический путь INI проверяет этот результат и сохраняет аварийный вывод в stderr/отладчик при отказе логгера.

Подключены события конфигурации, запуска и завершения, устройств и рендер-пайплайна, компиляции шейдеров, импорта мешей/сцен, декодирования текстур, CPU-пакетов загрузки, создания сущностей/материалов и ожидания GPU-upload. В Tick/Update/Render и тело игрового цикла вызовы не добавлены. Старый `PEP_ENABLE_ASSET_DEBUG_LOGS` сохраняет своё назначение; при включении его сообщения также идут через очередь.

Очередь рассчитана на конечные этапы загрузки и не выбрасывает записи при наплыве. Перед добавлением покадровых логов понадобится отдельное решение по ограничению очереди. Принудительное завершение процесса/отключение питания не гарантирует сохранение ещё не записанных сообщений; обычное завершение и ошибки запуска используют drain/flush.

## Проверка

В Developer PowerShell Visual Studio из корня проекта:

```powershell
New-Item -ItemType Directory -Force Build/LoggerTests/Manual | Out-Null
cl /nologo /std:c++17 /EHsc /W4 /Z7 /IEngine/Engine.Core/Include Engine/Engine.Core/tests/LoggerTests.cpp Engine/Engine.Core/src/Logger.cpp Engine/Engine.Core/src/RuntimePaths.cpp /FoBuild/LoggerTests/Manual/ /FeBuild/LoggerTests/Manual/LoggerTests.exe /link kernel32.lib
Build/LoggerTests/Manual/LoggerTests.exe
```

Для Release добавьте `/DNDEBUG /O2`. Проверяются фоновое форматирование, отсутствие ожидания занятого писателя, копирование временных строк и UTF-8, параллельные производители, сохранение старого файла, drain при уничтожении и отказ файловой системы без зависания `Flush()`. Сообщение `Logging failed` в последнем тесте ожидаемо.

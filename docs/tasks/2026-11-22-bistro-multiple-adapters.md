# Bistro на трёх и более физических GPU

## Согласованный объём

Bistro должен одновременно использовать основной адаптер для сборки и показа кадра и несколько дополнительных для Cloud Picture, AO, частиц и SPH-воды. Список доступных GPU определяет оборудование при запуске. Число три задаёт размер первого испытательного стенда.

Для каждой техники пользователь выбирает одну GPU по имени в F1. Несколько техник могут выбрать одну и ту же GPU. Разные доступные адаптеры у двух техник являются допустимой конфигурацией. Например, при основной GPU [1] облака могут считать на [0], а вода на [2].

Размещение применяется к уже переносимой работе техники. Основная GPU по-прежнему может готовить входы, импортировать результат и рисовать его. Существующее размещение фильтра AO внутри пары сохраняется. Дробление SPH между картами, вынос фильтра AO на третью карту и прямой обмен между дополнительными GPU выходят за рамки задания.

## Настройки и синхронизация

Сохранить выбор основной GPU при запуске через `Render.PrimaryAdapter`. Для четырёх настроек `App.*.Adapter` значение `-1` означает локальное исполнение на текущей основной GPU. Неотрицательные числа сохраняют абсолютные индексы в списке оборудования рендера. Выбор размещения остаётся ручным.

Для каждой техники сохранить её режимы `CrossSync`, значения по умолчанию, правила первого кадра и выбора версии. Основная GPU синхронизируется с той картой, которая произвела нужный результат. Текущие правила перечислены в [таблице режимов Bistro](../../Apps/App/README.md#two-adapter-synchronization).

При смене карты техники в F1 применить выбор без перезапуска Bistro. Допускаются краткая пауза для завершения ранее отправленных GPU-команд и повторная инициализация изменённой техники. Остальные техники сохраняют своё размещение и состояние.

До создания устройств сверить индекс основной карты и запрошенные индексы дополнительных карт со списком оборудования рендера. Если хотя бы один из них отсутствует, применить общий сброс в этом же запуске:

- Установить `Render.PrimaryAdapter=0`.
- Установить `App.CloudPicture.Adapter`, `App.AO.Adapter`, `App.Particles.Adapter` и `App.Water.Adapter` в `-1`, включая ранее допустимые назначения.
- Сохранить эти пять значений в стартовой конфигурации рядом с исполняемым файлом. Сейчас при запуске Bistro копирует `Configs/Startup.ini` в `Config/Engine.ini`; следующий запуск должен прочитать уже исправленные назначения. Сохранить пользовательские значения `CrossSync`, качества и остальных настроек.
- Записать в журнал имя настройки, отсутствующий индекс и сообщение о переводе всех техник на основную GPU.

После сброса Bistro запускается на адаптере [0]. Пользователь может заново назначить дополнительные карты в F1.

## Приёмка

На физическом трёхкарточном стенде запустить Bistro с Cloud Picture на одной дополнительной GPU и SPH-водой на другой. В одном запуске подтвердить фактические устройства исполнения обеих техник, получение обоих результатов основной GPU и отображение картины и воды в сцене. Записать имена и индексы всех трёх устройств и наблюдаемые признаки работы. Критерий приёмки функциональный, без целевого прироста FPS.

Журнал должен указать имя и индекс фактического исполнителя каждой техники и первый импорт результата каждой удалённой техники основной GPU с указанием источника. Для подтверждения достаточно обычного запуска, изображения сцены и записей об импортах с двух разных физических GPU.

# Bistro MGPU — экранный игровой HUD

Третий этап после теней. Перенести отрисовку игрового HUD в прозрачный экранный слой на выбранном адаптере. Изображение сцены остаётся на адаптере финальной композиции. В обычном запуске HUD сохраняет текущее поведение на GPU0. `App.UI.Game.Adapter = -1` выбирает основную карту. Аппаратный индекс второй карты включает Exact на владельце. `Render.UI.Game.Enabled` и `Render.UI.Game.Quality` действуют в обоих режимах.

## Задание

1. Источники — `Apps/App/src/Techniques/UI/BistroGameHUD.h`, `ScenePostUI::AppendScreen` и backend `Engine.UI`. Внешний референс — `MGPU-IMGUI/HybridUIApp.cpp`, где второй GPU рисует UI-текстуру, а основной импортирует её для композиции. В Bistro переиспользовать уже существующие запись draw data, таблицу текстур и механизмы защиты кадровых слотов.
2. Оставить CPU-подготовку HUD привязанной к текущим display size, DPI, времени и игровым данным. Доставить владельцу неизменяемый набор draw lists кадра, шрифтовый атлас и атлас Bistro. Процедурную health bar с GPU sparks рассчитать на владельце перед HUD raster. Сохранить UV, clip rectangles, цвета и действующее alpha-смешивание текста и полупрозрачных элементов.
3. Передать готовый HUD одним прозрачным слоем нужного экранного разрешения. Привязать точный импорт к композиции HUD, чтобы более ранние проходы сцены могли исполняться параллельно. Сохранить порядок игрового HUD, информационного/debug UI, texture inspector и финального Present. Готовый слой без debug UI можно получить через `ScenePostUI::OwnerHudLayer()` после `SubmitHud`. В публикации есть адаптер, текстура в `COMMON` и fence готовности. Следующий этап сможет использовать эту текстуру у владельца, когда он совпадёт с адаптером вывода. На GPU0 игровой и debug UI используют общую текстуру. Для вывода на другом GPU этап 04 должен взять игровой слой до записи debug UI. World-space canvases, posters и их настройки сохраняют отдельный путь.
4. При выключении HUD убрать устаревший слой и его обмен. При resize, изменении DPI, обновлении атласа или смене адаптера пересоздавать только нужные ресурсы и учитывать незавершённые чтения. Базовый маршрут сохраняет выбранный пользователем уровень `Render.UI.Game.Quality`.

## Приёмка

Release и один короткий обычный smoke с включённым экранным HUD. Показать выполнение HUD raster на выбранной GPU, использование импортированного слоя в оконном кадре и корректный порядок поверх сцены. Проверить по коду обработку прозрачного фона и кадровых слотов. В отчёте дать настройки, размер слоя, коммит и лог.

Проверка Release x64 на RTX 5050 и Arc B570 подтверждена. Размер и fences зафиксированы в [отчёте](../reports/2026-11-22-bistro-mgpu-screen-hud-midspec.md).

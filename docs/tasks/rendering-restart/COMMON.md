## CVar — обязательная часть каждой техники

Для постэффектов первой группы включение, Off/Low/Mid/High (если алгоритм масштабируется), выбор реально поддерживаемого алгоритма и его рабочие параметры управляются существующей CVar-системой. Для компонентной второй группы глобально регистрируются только Enabled и Quality; остальные поля принадлежат компоненту, согласно уточнению выше. Все runtime-настройки имеют Default, а не ReadOnly: их можно менять из C++ через ConsoleModule и из `Config/Engine.ini`. Регистрируй один static AutoConsoleVariable в .cpp до загрузки INI; не создавай отдельную регистрацию на каждую единицу компиляции через header statics. Изучи actual owning code и docs/console-variables.md.

Проверяй finite/ranges/enums на границе; используй безопасный snapshot на кадр. Пресеты должны менять фактическую работу GPU. Реализация и качество независимы; не создавай пустые Implementation-переключатели для единственного алгоритма. Ручные overrides не перезаписываются сменой качества; явное inherit/preset значение возвращает управление пресету. Глобальные множители не изменяют author fields компонентов. Безопасно обрабатывай runtime переключения, disable/re-enable, resize и историю. Обнови Engine.ini и справку только для реально глобальных CVar, а документацию defaults/единиц/диапазонов — также для полей компонентов. CPU-тесты CVar выполняет проверяющий.

## Интеграция

Один GPU. Не менять multi-GPU на этом этапе. Не добавлять entities, демонстрационные объекты, камеры, probes, volumes, материалы или тестовые модели в Bistro и не создавать новую demo scene. Небольшие изолированные CPU/GPU fixtures разрешены. Сохрани существующие PBR, direct lighting, local/CSM shadows, WBOIT, движение существующих объектов и GPU-driven draws.

Правильно согласуй линейный HDR, reverse-Z, RH matrices, normal spaces, сантиметры сцены, depth и motion. Нельзя наслаивать AO или specular energy повторно. При необходимости раздели HDR composition и финальное tone mapping минимальным изменением текущих passes; эффекты не должны получать уже clipped LDR. Не строй универсальный render-graph framework. XeSS должен работать с корректным HDR, jitter и resetHistory. Нужное положение эффекта относительно апскейлера обоснуй изображением и стоимостью. Синтетический fixture не объявляй визуальной проверкой Bistro.

Независимые задачи могут получить похожие минимальные изменения общей HDR-интеграции. В финальном отчёте явно отдели их и опиши контракт inputs/outputs, чтобы потом объединить код без дублирования. Не придумывай дополнительные общие менеджеры для гипотетического merge.

## Интеграционная база после первой группы

В REVIEW добавлен depth prepass. `Render.AO.ExecutionPoint`: 0 — AO сразу после препасса с normals, 1 (default) — AO перед освещением, препасс только depth + alpha-test. В позднем режиме отдельные DepthVS/DepthPS не считают normals/материальные G-buffer поля. Основные CSM/local shadows идут после препасса (и раннего AO, когда он выбран). Opaque использует общий depth с Equal и без depth writes. Новая opaque/masked геометрия второй группы обязана поддерживать оба препасс-пути вместе с main/shadows/probes/motion. Порядок HDR: deferred → SSSR resolve → WBOIT composition → DoF → motion blur → HDR XeSS → единственный tone mapping. SSSR SDK miss fallback уже согласован с local probes; не возвращать глобальный-only fallback.

# Bistro. Владелец страницы локальных теней и возврат глубины на GPU0

Исходная реализация фиксированных атласов — `064251ba`. GPU сейчас назначается фонарю, статическая глубина строится на GPU0, а назначенный адаптер получает изменённые статические тайлы и дорисовывает динамические объекты. Перенести владение на физическую страницу атласа. Её владелец строит и хранит статическую глубину, восстанавливает из неё нужные тайлы и рисует динамических кастеров. Основное освещение на GPU0 получает итоговую глубину. [Исходное задание по атласам](2026-11-24-bistro-local-shadow-atlases.md) · [Текущий путь рендеринга](../../Apps/App/src/Techniques/SceneLighting.cpp)

## Назначение и размещение

- Дать пользователю выбор адаптера отдельно для каждой активной страницы через существующие настройки Bistro. Индекс страницы стабилен в рамках профиля. По умолчанию и при отсутствии выбранного адаптера владелец — GPU0. Обновить UI, применение настроек и существующие места подбора/чтения владельца, которые сегодня предполагают один GPU на фонарь. При загрузке старой конфигурации обеспечить рабочий переход и однозначно показывать действующие назначения.
- Владельца грани определяет страница, выделенная упаковщиком. На странице ровно один писатель. Прожектор занимает один тайл, шесть граней точечного источника получают общий уровень детализации и могут лежать на разных страницах. Если владельцы страниц разные, каждый строит свои грани. Сохранить гарантии размещения малых теней для видимых источников, стабильность адресов и существующие правила Exact/Latest.
- Сохранить `Render.Shadows.Local.AtlasCount`, ручной потолок 384 и пресеты. Максимальные грани Low/Medium/High/Epic — 128/256/512/1024, стороны страниц — 512/1024/2048/4096. Меняется только путь локальных теней. Каскады солнца имеют собственное размещение.

## Работа владельца

- Для каждой принадлежащей адаптеру страницы выполнять там обе стадии. Инвалидировать статические тайлы по изменениям света, размещения и статических кастеров. Изменение динамического кастера должно обновить затронутый итоговый тайл, в том числе убрать тень ушедшего объекта. Для локальных страниц GPU0 сразу использует результат. Удалённым страницам передавать входы сцены через существующие зеркала: геометрию, изменения деформации, трансформы, маскированные материалы и необходимые данные растительности. Убрать прежнюю подготовку на GPU0 и отправку статической глубины владельцу удалённой страницы.
- Основное освещение, прозрачность и отражения должны читать согласованные адреса и готовые версии. Для потребителя статической глубины сохранить именно статическое содержимое. Переиспользовать существующую передачу ресурсов и ожидания между адаптерами. В бюджете каждого GPU учитывать принадлежащие ему страницы, зеркала у потребителей, кадровые слоты и ресурсы передачи. Проверить, что GPU-владельцу одной страницы не выставлена стоимость всего набора как собственной статической и итоговой глубины. ## Передача владельцем результата

- Решение принимать отдельно для каждой страницы и версии, нужной получателю. Составить набор тайлов, содержимое которых изменилось относительно версии у получателя. Учитывать отставание на несколько кадров, пропущенные публикации, перемещения и переиспользование тайла. Идентичное готовое содержимое не требует передачи. При первом получении или смене поколения инициализировать всё содержимое, которое потребитель может читать.
- Считать покрытие как площадь объединения передаваемых прямоугольников в текселях, делённую на полную площадь страницы. Стартовый порог для «почти всей страницы» — **75% включительно**, одна именованная константа. Ниже порога пакетировать и возвращать изменённые тайлы. На пороге и выше возвращать один полный слой массива, соответствующий этой странице. Например, для High каждый тайл 512² занимает 1/16 страницы 2048². Один такой тайл передаёт 1 МиБ D32, двенадцать неперекрывающихся тайлов включают передачу всей страницы объёмом 16 МиБ. Это начальная инженерная настройка, а не измеренная точка выигрыша.
- Целая страница должна быть согласованным снимком с сохранёнными чистыми тайлами. Копировать слой через поддержанный устройствами межадаптерный ресурс. Полностраничный путь должен устранять упаковку и отрисовку отдельных прямоугольников для этой передачи. При несовместимых версиях, неполностью готовой странице или риске затереть более свежие тайлы у потребителя использовать корректную передачу тайлов. [Передача тайлов](../../Apps/App/src/Techniques/LocalShadowTileCopy.h) · [Транспорт между адаптерами](../../Apps/App/src/Techniques/ShadowDepthTransfer.h)
- В Exact потребитель ждёт fence необходимой публикации перед чтением. В Latest использует совместимую завершённую публикацию, для первого результата сохраняется существующий Exact bootstrap. На общей странице учитывать обе политики. Передача всей страницы не должна откатывать готовый Exact-тайл при позднем завершении Latest. Удерживать экспортированную версию до завершения читателей, при смене владельца, размера или числа страниц инвалидировать прежнее поколение.

## Приёмка

Сборка Release и короткий обычный smoke Bistro с удалённой страницей на доступной паре GPU. Подтвердить, что владелец выполнил статический и динамический проходы, GPU0 получил глубину и использовал её при освещении. Для выбора тайлов или целой страницы проверить условие и адресацию в коде и указать, какой путь наблюдался в обычном запуске. Если какой-либо путь проверен только чтением кода, отметить это. Статистика атласов остаётся доступной для ручного просмотра по текущей раскладке. Новую запись метрик в CSV, логи или файлы и отдельное профилирование в задачу не включать.

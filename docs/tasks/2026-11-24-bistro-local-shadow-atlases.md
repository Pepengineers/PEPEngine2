# Bistro. Фиксированные атласы локальных теней

Задание для отдельного исполнителя. Основание — реализация на `8f6135c0`. Ниже заданы размеры страниц для каждого профиля. Поведение при полностью занятых страницах описано в разделе о размещении граней.

## Результат

Заменить растущие массивы глубины по разрешениям на заранее выделенные страницы атласа для точечных источников и прожекторов. Страница принимает квадратные грани разных размеров. При включении локальных теней выделять полную ёмкость действующего профиля. Число видимых фонарей и движение камеры меняют содержимое страниц при постоянных размерах текстур. Работы касаются локальных теней Bistro.

Сохранить существующий выбор желаемого разрешения по вкладу источника в изображение основной камеры, гистерезис и стабильный ID. Источник за камерой может освещать видимую стену. Основное освещение использует опубликованное размещение. WBOIT освещает прозрачные поверхности по параметрам источников и использует глубину непрозрачного препасса. Предыдущий план описывает исходную реализацию. [Адаптивное разрешение](../plans/2026-11-24-bistro-local-shadow-resolution.md) · [Текущий выбор и хранение](../../Apps/App/src/Techniques/SceneLocalShadows.cpp)

## Как размещать грани

1. Рассчитать раскладку до записи команд рисования. Обрабатывать источники по убыванию экранного вклада, при равенстве использовать существующий стабильный ключ. Сохранять пригодное прежнее размещение, когда оно совместимо с распределением по приоритету.
2. Для нового размещения начать с желаемого размера грани. Проверить свободные прямоугольники первой страницы, затем второй и далее. Если запрос не поместился ни на одной странице или комбинации страниц, перейти на следующую меньшую ступень и повторить с первой. Например, при потолке 512 последовательность для крупного фонаря — 512, 256, 128, 64, 32, 16. Сохранить поддерживаемый потолок 384 и существующие ступени ниже него.
3. Прожектору выделить один квадрат. Для точечного источника резервировать шесть квадратов одного размера. Предлагаем разрешить граням находиться на разных страницах. Подбирать место для комплекта целиком, откатывать пробные резервы перед попыткой меньшего размера. Обновлять только востребованные грани согласно действующему кэшу. Размещение и маску готовых граней публиковать согласованно.
4. Предлагаем при полном атласе отдавать место источникам с большим вкладом при очередном расчёте. Если все более важные источники уже размещены и даже минимум не помещается, текущий фонарь продолжает светить без карты. Уменьшение только новой заявки помогает, пока в атласах есть подходящее свободное место. Например, на High шестнадцать граней по 512 полностью занимают страницу 2048². Следующая грань любого размера требует другой страницы либо освобождения места.

Для сравнения, URP 6.0 собирает заявки на видимые локальные тени в один атлас. При тесной упаковке применяет общий делитель к запрошенным сторонам и может исключить низкоприоритетные источники при достижении минимума. Для Bistro последовательный поиск по страницам и уменьшение отдельной заявки позволяют сохранить качество ранее размещённых приоритетных теней. [Упаковщик Unity](https://github.com/Unity-Technologies/Graphics/blob/6000.0/staging/Packages/com.unity.render-pipelines.universal/Runtime/Passes/AdditionalLightsShadowAtlasLayout.cs)

## Профиль и память

Для локальных теней предусмотреть пять именованных уровней — Off, Low, Medium, High и Epic. Low включает тени и участвует в автоматическом понижении между Medium и Off. Сегодня поиск перечисляет только Off, Medium, High и Epic. Обновить выбор в UI и кандидаты автоподбора. Сохранить смысл существующих числовых настроек как потолка грани, включая 128 и 384. [Уровни поиска](../../Apps/App/src/BistroPlacementSearch.h)

Использовать одну таблицу профилей в настройках, автоматическом подборе и аллокаторе. Страница — квадратная поверхность для размещения нескольких карт теней. Число страниц задаёт целочисленная CVar `Render.Shadows.Local.AtlasCount`, по умолчанию 4. Для включённых теней поддержать положительные значения в пределах возможностей реализации и устройства, включая 1, 2, 3 и 4. При Off выделять ноль страниц. Сторону страницы и потолок грани брать из профиля. Применять число страниц к физическому выделению, упаковке и оценке бюджета на каждом участвующем GPU. При изменении настройки безопасно заменить ресурсы с учётом команд в полёте.

Таблица рассчитана для четырёх страниц на основном GPU, D32 (4 байта на тексель), двух версий глубины и трёх кадровых слотов. При трёх страницах объём данных глубины составляет ¾ указанной величины. Выравнивание D3D12, зеркала и временные передачи учитываются дополнительно.

| Профиль | Страницы атласа | Потолок грани | Одна версия в одном слоте | Статическая и итоговая, три слота |
|---|---:|---:|---:|---:|
| Off | 0 | 0 | 0 | 0 |
| Low | 4 × 512² | 128 | 4 МиБ | 24 МиБ |
| Medium | 4 × 1024² | 256 | 16 МиБ | 96 МиБ |
| High | 4 × 2048² | 512 | 64 МиБ | 384 МиБ |
| Epic | 4 × 4096² | 1024 | 256 МиБ | 1536 МиБ (1,5 ГиБ) |

Каждый включённый профиль вмещает до 16 граней максимального размера на страницу, всего 64 при четырёх страницах до учёта возможных полей фильтра. Стартовый потолок 512 соответствует High. Для нового Low использовать уже поддерживаемый потолок 128. Сохранить ручной вариант 384 со страницами 768² (54 МиБ при четырёх страницах). [Валидация разрешения](../../Engine/Engine.RendererDX12/Include/Engine.RendererDX12/GDX12LocalLights.h) · [Стартовая конфигурация](../../Apps/App/Configs/Startup.ini)

Перед выделением проверить реальную стоимость через D3D12 по каждому участвующему адаптеру. Учесть кадровые слоты, статическую и итоговую глубину, зеркала, передачу Exact/Latest и ресурсы, ожидающие fence. Выбрать ближайший доступный профиль не выше запрошенного, вплоть до 0. Отображать запрошенный и действующий уровни и причину понижения. При смене профиля учитывать пик одновременного существования ресурсов либо дождаться завершения старых читателей. Заполнение страниц внутри одного профиля обрабатывает упаковщик. [Расчёт VRAM](../../Apps/App/src/BistroVideoMemory.h) · [Подбор качества](../../Apps/App/src/BistroPlacementSearch.h)

## Изменения в рендерере

- Представлять каждую опубликованную грань номером страницы, прямоугольником в текселях, действующим размером и поколением размещения. Равные страницы удобно хранить слоями одной `Texture2DArray`. Тогда все размеры доступны через один SRV, в том числе в существующем пути без индексирования отдельных текстур.
- Настроить viewport, scissor и очистку в пределах тайла. Преобразовать UV грани в UV страницы. Считать смещения PCF в текселях и ограничить каждую фильтруемую выборку внутренними центрами крайних текселей тайла. Учитывать размер грани при расчёте bias. Использовать опубликованную адресацию в deferred lighting. [Чтение локальных теней](../../Engine/Engine.RendererDX12/Shaders/LocalShadows.hlsli)
- Перевести восстановление статической глубины и передачу изменённых граней на прямоугольники. В D3D12 операция `CopyTextureRegion` для depth-stencil требует целого подресурса. Для тайла переиспользовать подход шейдерного извлечения и записи глубины. Сохранить текущую семантику Exact/Latest, готовность данных и защиту от чтения тайла, уже отданного другому фонарю. [Передача тайлов в Bistro](../../Apps/App/src/Techniques/SunShadowTileTransfer.h) · [Публикация локальных теней](../../Apps/App/src/Techniques/SceneLighting.cpp) · [Ограничение D3D12](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12graphicscommandlist-copytextureregion)
- Убрать зависящее от числа граней создание и расширение массивов по разрешениям. Для переноса тайла использовать свободное место профиля или дождаться безопасного переиспользования. При стабильной сцене сохранять адреса и кэш. Для ручной проверки в открытой панели существующей диагностики брать число занятых и выделенных страниц непосредственно из текущей раскладки. Страница занята, пока у неё есть хотя бы один зарезервированный тайл, включая кэш и ещё используемые поколения.

## Приёмка

Собрать Release и выполнить короткий обычный smoke Bistro с включёнными локальными тенями. При движении камеры видны тени фонарей, GPU выполняет теневой проход, явных ошибок нет. В коде проверить, что изменение количества востребованных граней при том же профиле не вызывает роста текстур. Для MGPU указать фактически проверенную конфигурацию. Занятость страниц и подходящее значение `AtlasCount` владелец проверит позже вручную или отдельной задачей.
